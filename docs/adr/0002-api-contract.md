# ADR-0002: API 계약 연결

- 상태: 채택
- 날짜: 2026-11-05

## 배경

BE와 FE가 같은 API 계약을 쓰고, 어긋나면 빌드에서 바로 알 수 있어야 합니다. MCP 서버도 나중에 같은 계약에서 Java 클라이언트를 생성합니다.

## 결정

| 항목 | 결정 |
| ---------------- | -------------------------------------------------- |
| 스펙 생성 | springdoc 3.2.0 |
| 스펙 추출 | BE 테스트에서 추출해 커밋된 파일과 비교 |
| 계약 파일 | `contracts/openapi/backend.json` (커밋) |
| FE 코드 생성 | Orval 8.46.0 (`frontend/src/api/generated/`, 커밋 안 함) |
| API 문서 노출 | 기본 끔, `OPENAPI_DOCS_ENABLED=true`로 켬, Swagger UI 없음 |
| 패키지 관리자 | npm |

## 근거

- 테스트에서 추출하면 서버를 띄우지 않아도 되고, DB가 붙은 뒤에도 Oracle 없이 동작합니다.
- 계약 파일을 커밋하면 어떤 API가 바뀌었는지 diff로 볼 수 있습니다.
- Orval은 타입과 API 함수를 함께 만들고, TanStack Query 훅으로 이어갈 수 있습니다.
- npm은 Node에 포함되어 있어 추가 반입이 필요 없습니다.

## 알려진 한계

- 스펙에 `required`가 없어서 생성된 타입의 필드가 모두 선택 값입니다.
- 스펙에 200 응답만 있습니다. 런타임에는 에러 응답도 오지만 타입에는 나타나지 않습니다. 5단계의 공통 에러 처리에서 해결합니다.

## 다시 볼 조건

- 화면 개발에서 선택 값 처리가 부담되면 DTO에 필수 표시를 추가합니다.
- 8단계에서 MCP 서버용 Java 클라이언트 생성기를 정합니다.
