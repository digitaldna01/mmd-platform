# ADR-0007: 입력 컴포넌트의 동작 라이브러리

- 상태: 채택
- 날짜: 2026-11-20

## 배경

선택 상자부터는 동작이 많습니다. 목록 열기와 닫기, 키보드 이동, 글자로 찾기, 스크린 리더 알림, 화면 끝에서 위로 열기, 한글을 조합하는 중의 검색이 필요하고, 뒤에 올 날짜·기간 선택, 다이얼로그, 메뉴도 같습니다. 이 동작을 직접 만들면 회사 서버의 모델이 고치다가 깨뜨리기 쉽습니다.

ADR-0003은 UI 라이브러리를 상용 그리드 선정 뒤로 미뤘습니다. 그리드는 표만 맡고 입력 컴포넌트는 그리드와 상관없이 필요해서, 입력 컴포넌트의 동작 라이브러리를 먼저 정합니다. 모양은 라이브러리가 아니라 디자인 토큰으로 그립니다.

## 결정

React Aria Components(Adobe, Apache-2.0)를 씁니다. 모양이 없고 동작만 있는(headless) 라이브러리입니다.

| 항목 | 결정 |
| --- | --- |
| 버전 | `react-aria-components` 1.22.1 |
| 감싸기 | `src/shared/ui`의 컴포넌트(`TextInput`, `Select` 등)만 React Aria를 가져옵니다. 화면은 이 컴포넌트를 씁니다 |
| 모양 | React Aria가 붙이는 상태 속성(`data-hovered`, `data-focused`, `data-invalid`, `data-disabled`, `data-open`)에 CSS Modules와 토큰으로 그립니다 |
| 언어 | `shared/ui/UiProvider`가 `ko-KR`로 고정합니다. 다른 언어의 안내 문구는 `@react-aria/optimize-locales-plugin`(2.1.0)이 빌드에서 뺍니다 |
| 층 | React Aria가 목록에 붙이는 z-index(100000)를 빼고 `--z-popover`를 씁니다 |
| 그대로 두는 것 | `Button`, `Tooltip`은 이미 만든 것을 씁니다 |
| 검사 | `shared/ui/boundaries.test.ts`가 `shared/ui` 밖의 React Aria 사용과 `<button>`, `<input>`, `<select>`, `<textarea>` 직접 사용을 막습니다 |

## 근거

같은 컴포넌트를 묶어 크기를 쟀습니다(React 제외, 압축 gzip, 2026-11-20). 그때 앱 JS는 97KB였습니다.

| 안 | 입력창 + 선택 상자 + 검색 선택 | + 날짜·기간 선택 | 다이얼로그, 메뉴, 숫자 칸, 체크박스, 탭까지 | 반입 패키지 |
| --- | --- | --- | --- | --- |
| React Aria Components 1.22 (한국어·영어만) | 63KB | 98KB | 113KB | 13 |
| Base UI 1.9 | 63KB | 날짜 선택 없음 | 110KB | 9 |
| Radix UI 1.8 | 검색 선택 없음 | 날짜 선택 없음 | 45KB | 74 |
| 직접 만들기 | 약 10KB | 약 20KB | - | 0 |

- 날짜·기간 선택(달력)까지 있는 것은 React Aria뿐입니다. 거의 모든 조회 조건에 기간이 있습니다.
- Base UI는 크기가 같지만 날짜 선택이 없어 다른 라이브러리를 더하거나 직접 만들어야 합니다.
- Radix는 값이 많은 선택 상자(검색)와 날짜 선택이 없습니다.
- 직접 만들면 가장 작지만 키보드, 스크린 리더, 위치 계산, 한글 입력을 모두 우리가 고쳐야 합니다.

## 결과

- 운영 번들이 커집니다. 입력 컴포넌트만 쓰면 약 60KB(gzip), 날짜 선택까지 쓰면 약 95KB가 늡니다. 사내망에서 한 번 받으면 캐시되므로 받아들입니다.
- React Aria의 컴포넌트 API는 부품이 많습니다. 화면에서는 `shared/ui`의 단순한 props만 씁니다.
- 날짜 입력은 표기 규칙(`2026-11-20`)을 따라야 합니다. 날짜 컴포넌트를 만들 때 React Aria의 날짜 칸이 이 표기를 내도록 맞춥니다.
- 상용 그리드의 셀 편집기도 가능하면 `shared/ui`의 컴포넌트를 씁니다. 그리드를 고른 뒤 확인합니다.
