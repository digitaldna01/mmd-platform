# ADR-0006: 컨테이너 배포와 이중화

- 상태: 채택
- 날짜: 2026-11-05

## 배경

지금은 Docker로 기동하되, 쿠버네티스로 옮길 때 코드와 이미지는 바꾸지 않고 배포 정의만 바꾸는 것이 목표입니다. BE 2개 구성으로 이중화를 일찍 검증합니다.

## 결정

| 항목 | 결정 |
| --------------- | ---------------------------------------------------------- |
| 이미지 | 멀티 스테이지 빌드, 비루트 실행, 고정 버전 베이스 이미지 |
| Dockerfile 위치 | 각 모듈 폴더, 빌드 컨텍스트는 레포 루트 |
| 레지스트리 | `BASE_REGISTRY`로 교체 |
| JVM 메모리 | `MaxRAMPercentage=75` (컨테이너 한도 기준) |
| 게이트웨이 | FE와 분리한 별도 nginx |
| 재전송 | 연결 실패만 다른 BE로 넘김 |
| 구성 | `backend-1`, `backend-2`, `frontend`, `mcp-server`, `gateway` |

## 근거

- FE 이미지는 정적 파일만 담고 게이트웨이를 분리합니다. 쿠버네티스에서는 게이트웨이만 Ingress로 바뀌고 FE 이미지는 그대로 씁니다.
- 게이트웨이 설정은 이미지에 넣지 않고 마운트합니다. 호스트 이름을 이미지에 넣지 않는 규칙을 지키기 위해서입니다.
- 비루트 사용자는 숫자 UID로 지정합니다. 쿠버네티스의 `runAsNonRoot` 검사와 맞습니다.
- BE의 503, 504를 재시도하면 MMD 서버가 느릴 때 같은 요청이 두 번 나갑니다. 메시징의 "자동 재시도 없음" 원칙과 맞춥니다.
- `resolve`와 Docker DNS를 써서 컨테이너가 다시 만들어져도 게이트웨이를 재시작하지 않습니다.

## 검증 결과

- 요청을 계속 보내면서 정상 중지, 강제 종료, 순차 재생성을 진행해 실패 0건을 확인했습니다. (`deploy/compose/check-failover.sh`)
- 장애 전환을 끄면 같은 스크립트가 실패를 보고합니다.
- 처음에는 순차 재생성에서 간헐적으로 502가 났습니다. 원인은 교체 속도가 `fail_timeout`보다 빨랐던 것입니다. `fail_timeout`을 3초로 줄이고 인스턴스 사이에 5초를 기다리도록 고친 뒤 재현되지 않았습니다.

## 알려진 한계

- **멈춘 인스턴스를 빨리 감지하지 못합니다.** 프로세스가 죽지 않고 응답만 멈추면 nginx는 `proxy_read_timeout`(35초)까지 알 수 없어서, 그동안 요청의 절반이 대기합니다. nginx 오픈소스에는 능동 헬스 체크가 없습니다. 운영에서는 체크리스트대로 readiness를 로드밸런서에 연결하고, 쿠버네티스에서는 readiness probe가 이 역할을 합니다.
- 게이트웨이와 FE는 1개씩입니다. 게이트웨이 이중화(L4 또는 keepalived)는 인프라 구성에서 다룹니다.
- 세션 공유는 검증하지 않았습니다. 인증이 없어서 체크리스트의 "로그인 유지" 항목은 인증을 붙인 뒤 다시 확인합니다.
- TIBRV와 Oracle은 구성에 없습니다. rvd 배치와 Oracle 페일오버는 회사에서 검증합니다.
- arm64 PC에서만 빌드하고 실행했습니다. amd64 서버에서는 다시 확인합니다.
- 실패 시 재전송되지 않는 POST 동작은 POST API가 없어서 실제로 시험하지 않았습니다.
