# ADR-0003: FE 기반

- 상태: 채택
- 날짜: 2026-11-05

## 배경

5단계의 목표는 화면 배치를 만드는 것이 아니라, 새 화면을 바로 만들 수 있는 준비입니다. 배치 방식은 레거시 MDI 구조와 사용자의 실제 배치 습관을 확인한 뒤 정합니다.

## 결정

| 항목 | 결정 |
| -------------- | ------------------------------------------------------ |
| 기반 | React 19, Vite 8, TanStack Query 5 |
| 화면 띄우기 | 화면 ID 등록부와 화면 1개를 띄우는 `ScreenHost` |
| 화면 구조 | 데이터를 연결하는 `Screen`과 표시만 하는 `View`로 분리 |
| 컴포넌트 개발 | Storybook 10, `npm ci`에 포함 |
| 에러 처리 | `apiRequest`가 실패 시 `ApiRequestError`를 던짐 |
| 스타일 | CSS Modules와 CSS 변수 |
| 테스트 | Vitest와 Testing Library |

## 근거

- `ScreenHost`만 두면 배치 방식을 정할 때 이 부분만 바꾸면 됩니다.
- `View`는 받은 값만 그리므로 Storybook에서 BE나 API 모의 도구 없이 상태별로 확인할 수 있습니다.
- `apiRequest`가 실패 시 예외를 던지면 성공 값만 돌아오므로, 스펙에 200 응답만 있어도 타입과 실제 동작이 맞습니다.
- CSS Modules는 Vite에 포함되어 있어 추가 반입이 없고, 어떤 그리드를 골라도 영향을 받지 않습니다.
- 추적 ID는 사내망 HTTP에서도 되도록 `crypto.getRandomValues`로 만듭니다.
- 타임아웃은 구형 브라우저에서도 되도록 `AbortController`와 `setTimeout`으로 구현합니다.

## 이번에 넣지 않은 것

- 헤더, 메뉴, 탭, 도킹, 여러 화면 동시 열기: 화면 배치 결정 후
- 라우터: 화면은 URL이 아니라 화면 ID로 띄우며, 로그인을 만들 때 다시 검토
- UI 라이브러리와 실제 디자인 값: 상용 그리드 선정 후
- Playwright: 반입 부담이 커서 뒤로 미룸
- 401 재로그인 처리: 인증 단계

## 알려진 한계

- `npm audit`에 중간 등급 4건이 있습니다. 모두 Storybook 개발 도구의 하위 패키지(`glob`, `minimatch`)이며, 운영 번들에는 들어가지 않습니다. 자동 수정은 Storybook 8.5로 내리는 방식이라 적용하지 않았습니다. Storybook을 올릴 때 다시 확인합니다.
- 지원 브라우저가 확정되지 않았습니다. 확정되면 Vite 빌드 대상을 맞춥니다.
