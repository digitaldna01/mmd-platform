# 디자인 가이드

## 컨셉 (결정)

**정밀하고 차분한 화면 위에, 꼭 필요한 곳에만 LG 레드.**

MMD는 하루 종일 보는 업무 도구입니다. 브랜드 사이트처럼 화려하면 피로하므로, 색과 서체로 은은하게 드러내고 화면의 주인공은 데이터와 상태가 되게 합니다.

| 키워드             | 뜻                                          | MMD에서                                       |
| ------------------ | ------------------------------------------- | --------------------------------------------- |
| Precision(정밀)    | 촘촘한 데이터도 정렬과 간격으로 읽히게      | 수십 열짜리 기준정보 그리드가 기본 화면       |
| Clarity(명료)      | 지금 무엇이 유효하고 무엇이 문제인지 한눈에 | 사용, 미사용, 승인 대기, 반려를 배지로        |
| Calm(차분)         | 넓은 면은 뉴트럴, 레드는 점으로만           | 브랜드 레드는 로고와 활성 메뉴 표시선에만     |
| Intelligent (지능) | 에이전트와 자연스럽게 공존하는 화면         | 오른쪽 도킹 패널, 에이전트가 실행한 동작 표시 |

브랜드 사이트에서 가져오지 않는 것: 큰 히어로 이미지, 그라디언트 배경, 장식용 모션, 알약형 대형 버튼.

### 확인 기준 (결정)

화면을 검토할 때 아래 기준으로 컨셉이 지켜졌는지 확인합니다.

| 키워드      | 확인 기준                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| Precision   | 숫자 열은 오른쪽 정렬과 고정폭 숫자로 자릿수가 세로로 맞습니다. 같은 요소는 어느 화면에서나 높이와 간격이 같습니다. |
| Clarity     | 상태는 색과 글자를 함께 써서 흑백으로 봐도 구분됩니다. 빨강은 오류와 반려에만 나옵니다.                             |
| Calm        | 채도 있는 색은 상태 배지와 표시선에만 있습니다. 브랜드 레드는 로고 영역과 활성 메뉴 표시선에만 있습니다.            |
| Intelligent | 에이전트가 바꾼 값과 사람이 바꾼 값이 구분됩니다. 에이전트 패널을 열어도 그리드를 가리지 않습니다.                  |

레퍼런스는 항목별 결정의 근거에 적습니다.

## 색

### 원칙 (결정)

**브랜드 레드와 오류 빨강을 분리합니다.** 업무 화면에서 빨강은 반려, 저장 실패, 검증 오류를 뜻합니다. 브랜드 레드를 버튼이나 넓은 면에 쓰면 정상 화면이 오류처럼 보이므로, 브랜드 레드는 로고 영역과 활성 메뉴의 얇은 표시선, 로그인, 빈 화면처럼 업무 데이터가 없는 곳에서만 씁니다. 주요 버튼은 레드가 아니라 짙은 차콜입니다.

### 브랜드 (LG 공식 값, 결정)

| 토큰           | 값                   | 용도                                                       |
| -------------- | -------------------- | ---------------------------------------------------------- |
| brand-heritage | #A50034 Heritage Red | 로고 영역, 라이트의 활성 메뉴 표시선                       |
| brand-active   | #FD312E Active Red   | 로그인 화면, 빈 화면 안내처럼 업무 데이터가 없는 곳의 강조, 다크의 활성 메뉴 표시선 |

다크의 활성 메뉴 표시선은 Active Red를 씁니다(기본값, 사이드바 메뉴를 만들 때 화면에서 확인). Heritage Red는 다크 패널 위에서 2.3:1이라 보이지 않고, Active Red는 4.8:1입니다. 다크의 negative(`#FF847D`)는 더 밝은 산호색이라 Active Red와 구분됩니다. LG 로고를 넣는다면 다크 바탕에서는 흰색 단색 로고를 씁니다(LG 로고 규칙).

### 뉴트럴 (결정)

axon 방식을 씁니다. 회색 단계를 OKLCH 명도(L)로 정하고, 라이트는 LG Warm Grey와 같은 색상(85°)에 채도 0.003, 다크는 쿨(250°)에 채도 0.008을 줍니다. 순백과 순흑은 쓰지 않습니다.

| 역할               | 라이트              | 다크                |
| ------------------ | ------------------- | ------------------- |
| 창 바탕            | `#EFEEEC` (L 0.95)  | `#0C0F12` (L 0.165) |
| 패널               | `#FAFAF9` (L 0.985) | `#14171B` (L 0.205) |
| 그리드 머리글      | `#F1F0EE` (L 0.955) | `#1E2124` (L 0.245) |
| 안내 글자          | `#6A6967` (L 0.52)  | `#818589` (L 0.615) |
| 보조 글자          | `#4E4D4B` (L 0.42)  | `#AAAEB3` (L 0.75)  |
| 본문, 주요 버튼 면 | `#222120` (L 0.25)  | `#E1E3E5` (L 0.915) |

선, 마우스 올림, 선택은 투명도로 만들어 어떤 표면 위에서도 한 단계로 보이게 합니다. 선택 행은 면과 함께 글자색 2px 막대를 붙입니다.

| 역할        | 라이트 `rgb(20 18 14 / α)` | 다크 `rgb(255 255 255 / α)` |
| ----------- | -------------------------- | --------------------------- |
| 구분선      | 0.13                       | 0.08                        |
| 강한 테두리 | 0.26                       | 0.16                        |
| 입력창 테두리 | 0.50                     | 0.36                        |
| 마우스 올림 | 0.05                       | 0.04                        |
| 선택        | 0.13                       | 0.10                        |

값은 OKLCH 규칙으로 스크립트가 계산하고, `tokens.css`에는 hex로 넣습니다. OKLCH 값은 주석으로 남깁니다. CSS의 `oklch()`는 Chrome 111 이상이 필요한데, 지원 브라우저가 정해지지 않았고 구형 브라우저를 쓸 수 있기 때문입니다.

근거와 레퍼런스

- 4안(웜, 약한 웜, 무채색, axon 방식)의 글자 대비는 비슷했습니다(본문 14~16.7:1).
- 웜은 색상이 '승인 대기' 노랑과 거의 같아(85°, 83°) 선택 행이 경고처럼 보였습니다. axon 방식은 채도가 낮고 선택 행에 막대가 있어 겹치지 않습니다.
- 값은 axon과 helm에서 쓰면서 대비를 검사한 값입니다. Material 3도 회색 바탕에 브랜드 색상을 약하게 섞습니다.

입력창 테두리(기본값, 입력창 컴포넌트를 만들 때 화면에서 확인): 입력창과 선택 상자처럼 테두리로 알아보는 요소는 입력창 테두리를 씁니다. 패널 위에서 라이트 `#878684` 3.5:1, 다크 `#696B6D` 3.4:1로 WCAG 1.4.11(3:1)을 넘습니다. 강한 테두리는 1.78:1(다크 1.62:1)이라 입력창에는 쓰지 않습니다. 읽기 전용 칸과 비활성 칸은 강한 테두리를 그대로 써서 편집할 수 있는 칸과 구분합니다.

서버 목업 토큰과의 대응

서버 목업의 배경 토큰은 이름을 그대로 두고 값을 아래처럼 바꿉니다.

| 서버 목업 토큰 | 쓰는 곳                          | 바꿀 값                                                                        |
| -------------- | -------------------------------- | ------------------------------------------------------------------------------ |
| bg-app         | 앱 전체 배경                     | 창 바탕                                                                        |
| bg-surface     | 그리드, 입력 영역, 카드, 다이얼로그 | 패널                                                                        |
| bg-sunken      | 조회 조건 패널                   | 그리드 머리글과 같은 단계 (`#F1F0EE` / `#1E2124`)                              |
| bg-nav         | 사이드 메뉴                      | 창 바탕. 활성 항목만 패널 면을 씁니다                                          |
| bg-selected    | 그리드 선택 행                   | 선택 (투명도) + 2px 막대                                                       |
| bg-hover       | 보조 버튼, 그리드 행 마우스 올림 | 마우스 올림 (투명도)                                                           |
| bg-info        | 안내 배경, 저장 대상 행 강조     | 없앱니다. 정보용 파랑을 두지 않습니다. 안내는 bg-sunken, 저장 대상 행은 '수정된 행' 점으로 표시합니다 |
| bg-warning     | 주의 안내 배경 (데모 안내 등)    | warning-soft                                                                   |

### 의미색 (결정)

의미색은 넷만 둡니다. 정보용 파랑은 두지 않고, 안내는 무채색으로 씁니다.

| 토큰     | 쓰는 곳                                                              | 라이트                          | 다크                            |
| -------- | -------------------------------------------------------------------- | ------------------------------- | ------------------------------- |
| positive | 사용, 저장 완료                                                      | `#137738` oklch(0.50 0.13 150) | `#6FC884` oklch(0.76 0.13 150) |
| negative | 반려, 저장 실패, 검증 오류                                           | `#B63132` oklch(0.52 0.17 25)  | `#FF847D` oklch(0.75 0.15 25)  |
| warning  | 저장하지 않은 변경, 막지 않는 검증 경고, 수정 충돌, 경고 메시지     | `#8D5E00` oklch(0.52 0.11 75)  | `#E3B25A` oklch(0.79 0.12 80)  |
| agent    | 에이전트가 바꾼 값, 에이전트가 실행한 동작                           | `#6C4AB3` oklch(0.50 0.16 295) | `#B7A1F5` oklch(0.76 0.12 295) |

옅은 면(`-soft`)은 같은 색의 투명도입니다. 라이트는 0.12, 다크는 0.14입니다.

| 토큰          | 라이트                     | 다크                         |
| ------------- | -------------------------- | ---------------------------- |
| positive-soft | `rgb(19 119 56 / 0.12)`    | `rgb(111 200 132 / 0.14)`    |
| negative-soft | `rgb(182 49 50 / 0.12)`    | `rgb(255 132 125 / 0.14)`    |
| warning-soft  | `rgb(141 94 0 / 0.12)`     | `rgb(227 178 90 / 0.14)`     |
| agent-soft    | `rgb(108 74 179 / 0.12)`   | `rgb(183 161 245 / 0.14)`    |

네 색 모두 패널과 자기 옅은 면 위에서 4.5:1 이상입니다(가장 낮은 값 4.6:1). 값은 axon의 의미색과 같고, warning만 라이트 명도를 0.56에서 0.52로 낮췄습니다. 0.56은 옅은 면 위 배지 글자가 3.9:1이었습니다.

### 기준정보 상태 (결정)

토큰 이름은 서버 목업과 같습니다. 상태는 의미색과 모양을 함께 써서 흑백에서도 구분되게 합니다(WCAG 1.4.1).

| 토큰            | 상태      | 뜻                                | 글자      | 테두리               | 면              | 앞 표시                          |
| --------------- | --------- | --------------------------------- | --------- | -------------------- | --------------- | -------------------------------- |
| status-active   | 사용      | 승인되어 유효한 기준정보          | positive  | 없음                 | positive-soft   | 체크                             |
| status-inactive | 미사용    | 비활성 처리된 기준정보            | 보조 글자 | 없음                 | 뉴트럴의 '선택' | 없음                             |
| status-pending  | 승인 대기 | 등록/변경 요청 후 승인 전         | 보조 글자 | 1px 실선, 글자색     | 없음            | 시계 (아이콘 세트를 정하기 전에는 6px 점) |
| status-draft    | 초안      | 임시 저장, 미제출                 | 보조 글자 | 1px 점선, 글자색     | 없음            | 없음                             |
| status-rejected | 반려/오류 | 승인 반려, 저장 실패, 검증 오류   | negative  | 1px 실선, 글자색     | 없음            | ×                                |
| status-retired  | 폐기      | 삭제/만료되어 더 쓰지 않는 데이터 | 안내 글자 | 없음                 | 없음            | 없음. 행의 코드에 취소선, 행 글자는 안내 글자 |

그리드 안 표시

| 표시                        | 모양                                                                 |
| --------------------------- | -------------------------------------------------------------------- |
| 검증 오류 셀                | negative-soft 면, negative 1px 안쪽 테두리, negative 굵은 글자, 앞에 `!` |
| 에이전트가 바꾼 셀 (저장 전) | agent-soft 면, agent 굵은 글자, 앞에 2px 테두리의 원                  |
| 수정된 행 (저장 전)          | No 칸 앞에 본문색 6px 점                                             |
| 선택 행                     | 뉴트럴의 '선택' 면, 첫 칸에 본문색 2px 막대                          |
| 주의 메시지                 | warning 글자, 앞에 삼각형                                            |

규칙

- 상태 배지에는 항상 글자를 씁니다. 같은 목록의 상태끼리는 테두리, 면, 앞 표시가 달라 흑백에서도 구분됩니다.
- warning은 기준정보 상태에 쓰지 않습니다. 레코드의 상태가 아니라 지금 사용자가 확인해야 하는 신호에만 씁니다.
- 배지 글자에는 취소선을 긋지 않습니다. 12px 한글의 가로획이 지워집니다. 폐기는 행의 코드에 긋습니다.
- negative와 브랜드 레드는 같은 빨강 계열입니다(negative 25°, Heritage Red 15°, Active Red 28°). 색상으로는 구분되지 않으므로 쓰는 곳(색 원칙)과 모양(×, `!`)으로 구분합니다.
- 배지 크기와 모서리는 밀도 단계에서 정합니다. 무드보드에서는 높이 20px, 글자 12px SemiBold, 모서리 4px로 그렸습니다.

근거

- 승인 대기는 문제가 아니라 진행 중인 상태라 무채색으로 둡니다. 경고색을 쓰면 정말 주의가 필요한 신호와 구분이 흐려집니다.
- 에이전트는 바이올렛입니다. 상용 그리드의 선택과 포커스는 대개 파랑이라, 파랑을 쓰면 에이전트가 바꾼 셀과 헷갈립니다.
- 초안의 점선은 '아직 확정되지 않음'을 뜻합니다. 폐기는 더 쓰지 않는 데이터라 가장 흐리게 가라앉힙니다.
- 형태로 상태를 구분하는 방식은 axon의 '상태의 형태 문법'을 따랐습니다.

## 글꼴과 크기 (결정)

### 서체

| 쓰는 곳                              | 서체                                   | 적용                                                                                         |
| ------------------------------------ | -------------------------------------- | -------------------------------------------------------------------------------------------- |
| 본문, UI, 그리드                     | Pretendard Variable 1.3.9 (SIL OFL)    | npm `pretendard`의 dynamic subset woff2를 직접 제공합니다. 굵기는 400, 500, 600, 700만 씁니다 |
| 그리드 셀과 입력창의 코드·숫자·날짜  | Pretendard + 글꼴 기능                 | `font-variant-numeric: tabular-nums; font-feature-settings: "zero" 1, "cv05" 1, "cv08" 1;`    |
| 메시지 미리 보기, 로그, 화면 ID 줄   | D2Coding 1.3.2 (SIL OFL)               | npm `d2coding`의 `fonts/d2coding-full.woff2`(1.48MB)를 직접 제공합니다. 쓰는 화면에서만 내려받습니다 |
| 로그인 화면 제목, MMD 글자 로고      | LG EI Text                             | 글꼴 파일은 LG 자산이라 공개 저장소에 넣지 않고 회사 PC에서 추가합니다. LG EI Headline은 쓰지 않습니다 |

글꼴 순서

- 기본: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 고정폭: `D2Coding, Consolas, "Malgun Gothic", monospace`
- 브랜드: `"LG EI Text", "Pretendard Variable", Pretendard, "Malgun Gothic", sans-serif`

근거

- 그리드의 코드 열은 고정폭 글꼴 없이 Pretendard의 글꼴 기능으로 헷갈리는 글자를 구분합니다. `zero`는 빗금 0, `cv05`는 꼬리 있는 l, `cv08`은 세리프 있는 I입니다. 그리드가 한 글꼴로 유지됩니다. 일반 문장에는 켜지 않습니다. 꼬리 있는 l이 문장에서는 어색합니다.
- 고정폭 글꼴은 글자 칸이 세로로 맞아야 하는 곳에만 씁니다. D2Coding은 한글이 정확히 2칸이라 한글 값이 섞인 메시지도 열이 맞습니다. JetBrains Mono는 한글 글자가 없어 한글에서 정렬이 깨집니다.
- LG EI Text는 LG 전용 서체이고, MMD는 LG 계열사 시스템이라 쓸 수 있습니다(2026-11-20 확인). 서체로 브랜드를 드러내는 자리(로그인 화면 제목, 글자 로고)에만 씁니다. LG EI Headline은 LG 가이드상 캠페인·히어로용이라 쓰지 않습니다.
- LG EI Text에 한글 글자가 있는지와 Windows에서 작은 크기로 잘 보이는지는 공식 페이지에 없어 회사 PC에서 확인합니다. 한글 글자가 없으면 한글은 Pretendard로 표시됩니다.
- Pretendard와 D2Coding은 반입할 때 `docs/import-list.md`에 적습니다.

### 크기 단계

아래는 기준 크기입니다(보통 모니터, 글자 크기 '보통'). 한글은 12px 아래로 내리지 않습니다.

| 토큰     | 쓰는 곳                                  | 기준 | 굵기                                 | 줄 높이                     |
| -------- | ---------------------------------------- | ---- | ------------------------------------ | --------------------------- |
| text-xs  | 라벨, 배지, 캡션                         | 12px | 500 (배지 600)                       | 1.4                         |
| text-sm  | 그리드, 버튼, 입력창, 메뉴               | 13px | 400 (버튼 500, 그리드 머리글 600)    | 1.5 (그리드는 행 높이)      |
| text-md  | 읽는 글: 안내, 메시지, 에이전트 대화     | 14px | 400                                  | 1.6                         |
| text-lg  | 영역 제목                                | 16px | 600                                  | 1.4                         |
| text-xl  | 화면 제목                                | 20px | 700                                  | 1.3                         |
| text-2xl | 로그인·빈 화면 제목                      | 24px | 700                                  | 1.3                         |

한국어 문단은 `word-break: keep-all; overflow-wrap: anywhere`로 줄을 바꿉니다.

### 크기 조정: 모니터 보정과 글자 크기 설정

크기는 서로 다른 두 가지 이유로 바뀌며, 둘을 따로 둡니다.

| 축          | 정하는 방법                      | 목적                                               | 더하는 값          |
| ----------- | -------------------------------- | -------------------------------------------------- | ------------------ |
| 모니터 보정 | 자동. 사용자에게 보이지 않습니다 | 넓은 모니터에서 1px이 작게 보이는 만큼 보정합니다  | 모든 글자 +1px     |
| 글자 크기   | 사용자가 '보통'과 '크게'에서 고름 | 큰 글자가 필요한 사용자. 어느 모니터에서든 커집니다 | 모든 글자 +2px     |

둘 다 적용되면 +3px입니다. 행과 컨트롤 높이도 함께 바뀝니다. 간격(4px 단위)은 바뀌지 않습니다.

| 항목                       | 기준 | 넓은 모니터 | 크게 | 넓은 모니터 + 크게 |
| -------------------------- | ---- | ----------- | ---- | ------------------ |
| 그리드 글자 (text-sm)      | 13px | 14px        | 15px | 16px               |
| 그리드 행 높이             | 28px | 30px        | 32px | 34px               |
| 컨트롤 높이 (버튼, 입력창) | 32px | 34px        | 36px | 38px               |
| 배지 높이                  | 20px | 22px        | 24px | 26px               |

모니터 보정

- 모니터 폭 `screen.width`(CSS px)가 2,200px 이상이면 넓은 모니터입니다. 창 폭이 아니라 모니터 폭을 봅니다. 창 크기를 바꾸거나 화면을 나눠 써도 바뀌지 않고, 창을 다른 모니터로 옮길 때만 다시 계산합니다.
- `<html>`에 `data-screen="wide"`를 붙이고, 크기 토큰을 그 값에 따라 바꿉니다.

| 기기               | 흔한 배율 | 모니터 폭       | 구분        | 1px 실제 크기 |
| ------------------ | --------- | --------------- | ----------- | ------------- |
| LG 24" FHD         | 100%      | 1,920px         | 보통        | 0.277mm       |
| LG gram 14"~17"    | 125~200%  | 1,280~2,048px   | 보통        | 0.20~0.24mm (눈과 더 가까움) |
| LG 27" QHD         | 100%      | 2,560px         | 넓은 모니터 | 0.233mm       |
| LG 27" 4K          | 150%      | 2,560px         | 넓은 모니터 | 0.233mm       |
| LG 34" 울트라와이드 | 100%      | 3,440px         | 넓은 모니터 | 0.231mm       |

27" QHD에서 13px은 3.0mm로, 24" FHD의 3.6mm보다 16% 작습니다. 보정한 14px은 3.3mm입니다.

글자 크기 설정

- 화면 설정에 '글자 크기: 보통 / 크게'로 둡니다. 기본은 '보통'이고, 사용자별로 저장합니다. 서버 목업의 '밀도: 표준 / 넓게'를 이 이름으로 바꿉니다. 이 설정을 찾는 사람은 '밀도'보다 '글자'라는 말을 먼저 찾습니다.
- `<html>`에 `data-text-size="large"`를 붙입니다.
- 브라우저 확대(Ctrl +)는 항상 동작해야 합니다. 크기는 토큰으로만 쓰고, 200% 확대에서도 내용이 잘리지 않아야 합니다(WCAG 1.4.4).

## 반응형

### 그리드 (원칙, 상용 그리드를 고른 뒤 구체화)

그리드의 반응형은 글자 크기가 아니라 열 배치로 합니다. 글자 크기는 위의 단계를 따릅니다.

- 코드, 숫자, 날짜 열은 내용에 맞춘 고정 폭입니다. 공정명, 비고처럼 긴 글 열이 남는 폭을 차지합니다.
- 체크박스, No, 코드 같은 핵심 열은 왼쪽에 고정하고, 폭이 모자라면 나머지 열을 가로 스크롤합니다.
- 폭이 좁을 때(노트북에서 에이전트 패널을 연 경우 등) 수정자, 수정일시처럼 덜 중요한 열을 숨기거나 상세 패널로 옮깁니다. 열마다 우선순위를 둡니다.
- 열 순서, 너비, 숨김은 사용자별로 저장합니다.
- 행 높이는 고정 숫자로 그리드에 넘깁니다. 위의 표에서 현재 조합에 맞는 값을 씁니다.
