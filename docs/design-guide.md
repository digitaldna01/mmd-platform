# 디자인 가이드

## 컨셉 (결정)

**정밀하고 차분한 화면 위에, 꼭 필요한 곳에만 LG 레드.**

MMD는 하루 종일 보는 업무 도구입니다. 브랜드 사이트처럼 화려하면 피로하므로, 색과 서체로 은은하게 드러내고 화면의 주인공은 데이터와 상태가 되게 합니다.

| 키워드             | 뜻                                          | MMD에서                                       |
| ------------------ | ------------------------------------------- | --------------------------------------------- |
| Precision(정밀)    | 촘촘한 데이터도 정렬과 간격으로 읽히게      | 수십 열짜리 기준정보 그리드가 기본 화면       |
| Clarity(명료)      | 지금 무엇이 유효하고 무엇이 문제인지 한눈에 | 사용, 미사용, 승인 대기, 반려를 배지로        |
| Calm(차분)         | 넓은 면은 뉴트럴, 레드는 점으로만           | 브랜드 레드는 로고와 활성 메뉴 표시선에만     |
| Intelligent (지능) | 에이전트와 자연스럽게 공존하는 화면         | 오른쪽 도킹 패널, 에이전트가 실행한 동작 표시 |

브랜드 사이트에서 가져오지 않는 것: 큰 히어로 이미지, 그라디언트 배경, 장식용 모션, 알약형 대형 버튼.

### 확인 기준 (결정)

화면을 검토할 때 아래 기준으로 컨셉이 지켜졌는지 확인합니다.

| 키워드      | 확인 기준                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| Precision   | 숫자 열은 오른쪽 정렬과 고정폭 숫자로 자릿수가 세로로 맞습니다. 같은 요소는 어느 화면에서나 높이와 간격이 같습니다. |
| Clarity     | 상태는 색과 글자를 함께 써서 흑백으로 봐도 구분됩니다. 빨강은 오류와 반려에만 나옵니다.                             |
| Calm        | 채도 있는 색은 상태 배지와 표시선에만 있습니다. 브랜드 레드는 로고 영역과 활성 메뉴 표시선에만 있습니다.            |
| Intelligent | 에이전트가 바꾼 값과 사람이 바꾼 값이 구분됩니다. 에이전트 패널을 열어도 그리드를 가리지 않습니다.                  |

레퍼런스는 항목별 결정의 근거에 적습니다.

## 색

### 원칙 (결정)

**브랜드 레드와 오류 빨강을 분리합니다.** 업무 화면에서 빨강은 반려, 저장 실패, 검증 오류를 뜻합니다. 브랜드 레드를 버튼이나 넓은 면에 쓰면 정상 화면이 오류처럼 보이므로, 브랜드 레드는 로고 영역과 활성 메뉴의 얇은 표시선, 로그인, 빈 화면처럼 업무 데이터가 없는 곳에서만 씁니다. 주요 버튼은 레드가 아니라 짙은 차콜입니다.

### 브랜드 (LG 공식 값, 결정)

| 토큰           | 값                   | 용도                                                                                |
| -------------- | -------------------- | ----------------------------------------------------------------------------------- |
| brand-heritage | #A50034 Heritage Red | 로고 영역, 라이트의 활성 메뉴 표시선                                                |
| brand-active   | #FD312E Active Red   | 로그인 화면, 빈 화면 안내처럼 업무 데이터가 없는 곳의 강조, 다크의 활성 메뉴 표시선 |

다크의 활성 메뉴 표시선은 Active Red를 씁니다(기본값, 사이드바 메뉴를 만들 때 화면에서 확인). Heritage Red는 다크 패널 위에서 2.3:1이라 보이지 않고, Active Red는 4.8:1입니다. 다크의 negative(`#FF847D`)는 더 밝은 산호색이라 Active Red와 구분됩니다. LG 로고를 넣는다면 다크 바탕에서는 흰색 단색 로고를 씁니다(LG 로고 규칙).

### 뉴트럴 (결정)

axon 방식을 씁니다. 회색 단계를 OKLCH 명도(L)로 정하고, 라이트와 다크 모두 쿨(250°)을 씁니다. 채도는 라이트 0.003, 다크 0.008입니다. 라이트 패널(0.0015)과 다크 본문(0.004)은 채도를 반으로 줄입니다. 순백과 순흑은 쓰지 않습니다.

면은 메뉴, 본문 바탕, 패널 순서로 한 단계씩 밝습니다. 메뉴와 본문 바탕을 선이 아니라 면으로 나누고, 조회 조건과 그리드는 같은 패널 면에 둡니다.

- 라이트: 메뉴 → 본문 바탕 ΔL 0.025(1.07:1), 본문 바탕 → 패널 ΔL 0.019(1.05:1). 화면을 밝게 하려고 본문 바탕을 패널 쪽으로 올렸고, 패널의 경계는 구분선이 함께 맡습니다.
- 다크: 메뉴 → 본문 바탕 ΔL 0.025, 본문 바탕 → 패널 ΔL 0.04. 다크는 밝게 할 이유가 없어 본문 바탕과 패널은 그대로 두고 메뉴만 한 단계 어둡게 했습니다. 본문 바탕을 함께 올리면(0.02씩) 패널이 바탕에 묻혔습니다.

| 역할                        | 라이트              | 다크                |
| --------------------------- | ------------------- | ------------------- |
| 메뉴                        | `#EDEFF0` (L 0.95)  | `#07090C` (L 0.14)  |
| 본문 바탕                   | `#F5F7F9` (L 0.975) | `#0C0F12` (L 0.165) |
| 패널 (조회 조건, 그리드)    | `#FCFDFE` (L 0.994) | `#14171B` (L 0.205) |
| 그리드 머리글, 읽기 전용 칸 | `#EFF0F2` (L 0.955) | `#1E2124` (L 0.245) |
| 비활성 글자                 | `#8B8C8E` (L 0.64)  | `#66696D` (L 0.52)  |
| 안내 글자                   | `#68696B` (L 0.52)  | `#8F9397` (L 0.66)  |
| 보조 글자                   | `#4C4D4F` (L 0.42)  | `#AAAEB3` (L 0.75)  |
| 본문, 주요 버튼 면          | `#212223` (L 0.25)  | `#E1E3E5` (L 0.915) |
| 주요 버튼 마우스 올림       | `#343537` (L 0.33)  | `#CCCED0` (L 0.85)  |
| 주요 버튼 누름              | `#464849` (L 0.40)  | `#B9BBBD` (L 0.79)  |

그리드 머리글 단계(bg-sunken)는 라이트에서 본문 바탕보다 어둡고, 다크에서는 패널보다 밝습니다. 어느 쪽이든 패널 위에서 한 단계 다른 면으로 보입니다.

선, 마우스 올림, 선택은 투명도로 만들어 어떤 표면 위에서도 한 단계로 보이게 합니다. 선택 행은 면과 함께 글자색 2px 막대를 붙입니다.

| 역할          | 라이트 `rgb(17 18 20 / α)` | 다크 `rgb(255 255 255 / α)` |
| ------------- | -------------------------- | --------------------------- |
| 구분선        | 0.13                       | 0.08                        |
| 강한 테두리   | 0.26                       | 0.16                        |
| 입력창 테두리 | 0.50                       | 0.36                        |
| 마우스 올림   | 0.05                       | 0.04                        |
| 누름          | 0.09                       | 0.07                        |
| 선택          | 0.13                       | 0.10                        |
| 비활성 면     | 0.09                       | 0.07                        |

값은 OKLCH 규칙으로 스크립트(`frontend/scripts/build-tokens.mjs`)가 계산하고, `tokens.css`에는 hex로 넣습니다. OKLCH 값은 주석으로 남깁니다. CSS의 `oklch()`는 Chrome 111 이상이 필요한데, 지원 브라우저가 정해지지 않았고 구형 브라우저를 쓸 수 있기 때문입니다.

근거와 레퍼런스

- 4안(웜, 약한 웜, 무채색, axon 방식)의 글자 대비는 비슷했습니다(본문 14~16.7:1).
- 웜은 색상이 '승인 대기' 노랑과 거의 같아(85°, 83°) 선택 행이 경고처럼 보였습니다. axon 방식은 채도가 낮고 선택 행에 막대가 있어 겹치지 않습니다.
- 값은 axon과 helm에서 쓰면서 대비를 검사한 값입니다. Material 3도 회색 바탕에 브랜드 색상을 약하게 섞습니다.
- 다크의 안내 글자는 axon 값(L 0.615)에서 0.66으로 올렸습니다. 0.615는 떠 있는 면(`#282C2F`) 위에서 3.8:1, 그리드 머리글 단계(`#1E2124`) 위에서 4.4:1로 WCAG 4.5:1에 못 미쳤습니다(토큰 스크립트의 대비 검사에서 발견).

라이트를 웜에서 쿨로, 면 나눔을 바꾼 이유 (화면 틀을 만든 뒤 다시 정함)

- 라이트를 웜(85°)으로 두었더니 화면 틀 전체가 노랗게 보였습니다. 채도 0.003은 작은 견본에서는 거의 보이지 않지만 화면의 9할을 덮으면 색으로 느껴집니다. 4안을 비교할 때는 웜(0.0115), 약한 웜(0.0058) 옆이라 무채색처럼 보였습니다.
- 선, 마우스 올림, 선택, 그림자의 기준색이 axon의 `rgb(20 18 14)`(채도 0.0085)로 면의 약 3배라 그리드 행 구분선이 가장 노랬습니다. 지금은 기준색도 면과 같은 규칙(L 0.183, 같은 색상과 채도)으로 계산합니다.
- 회사 PC에서 함께 쓰는 Windows, Edge, Outlook은 무채색이나 쿨이라 그 옆에서 웜이 떠 보입니다. 다크가 이미 250°라 두 테마의 색상 규칙이 하나가 됩니다.
- 상태 색 구분은 웜과 쿨이 같습니다. 경고 옅은 면과 패널의 색 차이는 둘 다 ΔE 1.6, 선택 행과 경고 옅은 면은 4.0과 4.2입니다. 이 채도에서는 바탕의 색상이 의미색 구분에 영향을 주지 않습니다.
- 메뉴와 본문 바탕을 같은 면(1.00:1)으로 두었더니 메뉴가 선으로만 구분되고, 화면의 넓은 부분이 중간 회색이라 어두워 보였습니다. 서버 목업(메뉴 < 조회 조건 < 본문 바탕 < 그리드)처럼 면을 나누되, 순백 그리드는 오래 보면 눈부셔서 패널을 L 0.994로 두었습니다.
- 조회 조건을 그리드 머리글 단계(bg-sunken)로 두면 본문 바탕과 1.02:1이라 구분되지 않았습니다. 그래서 조회 조건은 그리드와 같은 패널 면입니다.

입력창 테두리(기본값, 입력창 컴포넌트를 만들 때 화면에서 확인): 입력창과 선택 상자처럼 테두리로 알아보는 요소는 입력창 테두리를 씁니다. 패널 위에서 라이트 `#878889` 3.5:1, 다크 `#696B6D` 3.3:1로 WCAG 1.4.11(3:1)을 넘습니다. 메뉴 면 위(메뉴 검색 칸)에서도 3.4:1입니다. 강한 테두리는 약 1.8:1(다크 1.6:1)이라 입력창에는 쓰지 않습니다. 읽기 전용 칸과 비활성 칸은 강한 테두리를 그대로 써서 편집할 수 있는 칸과 구분합니다.

### 의미색 (결정)

의미색은 넷만 둡니다. 정보용 파랑은 두지 않고, 안내는 무채색으로 씁니다.

| 토큰     | 쓰는 곳                                                         | 라이트                         | 다크                           |
| -------- | --------------------------------------------------------------- | ------------------------------ | ------------------------------ |
| positive | 사용, 저장 완료                                                 | `#137738` oklch(0.50 0.13 150) | `#6FC884` oklch(0.76 0.13 150) |
| negative | 반려, 저장 실패, 검증 오류                                      | `#B63132` oklch(0.52 0.17 25)  | `#FF847D` oklch(0.75 0.15 25)  |
| warning  | 저장하지 않은 변경, 막지 않는 검증 경고, 수정 충돌, 경고 메시지 | `#8D5E00` oklch(0.52 0.11 75)  | `#E3B25A` oklch(0.79 0.12 80)  |
| agent    | 에이전트가 바꾼 값, 에이전트가 실행한 동작                      | `#6C4AB3` oklch(0.50 0.16 295) | `#B7A1F5` oklch(0.76 0.12 295) |

옅은 면(`-soft`)은 같은 색의 투명도입니다. 라이트는 0.12, 다크는 0.14입니다.

| 토큰          | 라이트                   | 다크                      |
| ------------- | ------------------------ | ------------------------- |
| positive-soft | `rgb(19 119 56 / 0.12)`  | `rgb(111 200 132 / 0.14)` |
| negative-soft | `rgb(182 49 50 / 0.12)`  | `rgb(255 132 125 / 0.14)` |
| warning-soft  | `rgb(141 94 0 / 0.12)`   | `rgb(227 178 90 / 0.14)`  |
| agent-soft    | `rgb(108 74 179 / 0.12)` | `rgb(183 161 245 / 0.14)` |

네 색 모두 패널과 자기 옅은 면 위에서 4.5:1 이상입니다(가장 낮은 값 4.6:1). 값은 axon의 의미색과 같고, warning만 라이트 명도를 0.56에서 0.52로 낮췄습니다. 0.56은 옅은 면 위 배지 글자가 3.9:1이었습니다.

### 기준정보 상태 (결정)

이름은 서버 목업과 같습니다. 상태마다 글자, 테두리, 면, 앞 표시가 함께 정해지므로 CSS 토큰이 아니라 상태 배지 컴포넌트의 상태 이름으로 씁니다. 상태는 의미색과 모양을 함께 써서 흑백에서도 구분되게 합니다(WCAG 1.4.1).

| 이름            | 상태      | 뜻                                | 글자      | 테두리           | 면              | 앞 표시                                       |
| --------------- | --------- | --------------------------------- | --------- | ---------------- | --------------- | --------------------------------------------- |
| status-active   | 사용      | 승인되어 유효한 기준정보          | positive  | 없음             | positive-soft   | 체크                                          |
| status-inactive | 미사용    | 미사용으로 바꾼 기준정보          | 보조 글자 | 없음             | 뉴트럴의 '선택' | 없음                                          |
| status-pending  | 승인 대기 | 등록/변경 요청 후 승인 전         | 보조 글자 | 1px 실선, 글자색 | 없음            | 시계                                          |
| status-draft    | 초안      | 임시 저장, 미제출                 | 보조 글자 | 1px 점선, 글자색 | 없음            | 없음                                          |
| status-rejected | 반려/오류 | 승인 반려, 저장 실패, 검증 오류   | negative  | 1px 실선, 글자색 | 없음            | ×                                             |
| status-retired  | 폐기      | 삭제/만료되어 더 쓰지 않는 데이터 | 안내 글자 | 없음             | 없음            | 없음. 행의 코드에 취소선, 행 글자는 안내 글자 |

그리드 안 표시

| 표시                         | 모양                                                                     |
| ---------------------------- | ------------------------------------------------------------------------ |
| 검증 오류 셀                 | negative-soft 면, negative 1px 안쪽 테두리, negative 굵은 글자, 앞에 `!` |
| 에이전트가 바꾼 셀 (저장 전) | agent-soft 면, agent 굵은 글자, 앞에 2px 테두리의 원                     |
| 행 편집 상태 (저장 전)       | 편집 상태 열에 `+` 신규, `•` 수정, `−` 삭제 ('컴포넌트 > 그리드' 참고)   |
| 선택 행                      | 뉴트럴의 '선택' 면, 첫 칸에 본문색 2px 막대                              |
| 주의 메시지                  | warning 글자, 앞에 삼각형                                                |

규칙

- 상태 배지에는 항상 글자를 씁니다. 같은 목록의 상태끼리는 테두리, 면, 앞 표시가 달라 흑백에서도 구분됩니다.
- warning은 기준정보 상태에 쓰지 않습니다. 레코드의 상태가 아니라 지금 사용자가 확인해야 하는 신호에만 씁니다.
- 배지 글자에는 취소선을 긋지 않습니다. 12px 한글의 가로획이 지워집니다. 폐기는 행의 코드에 긋습니다.
- negative와 브랜드 레드는 같은 빨강 계열입니다(negative 25°, Heritage Red 15°, Active Red 28°). 색상으로는 구분되지 않으므로 쓰는 곳(색 원칙)과 모양(×, `!`)으로 구분합니다.
- 배지 높이는 '크기 조정' 표를 따릅니다(기준 20px). 글자는 text-xs SemiBold, 모서리는 3px입니다.

근거

- 승인 대기는 문제가 아니라 진행 중인 상태라 무채색으로 둡니다. 경고색을 쓰면 정말 주의가 필요한 신호와 구분이 흐려집니다.
- 에이전트는 바이올렛입니다. 상용 그리드의 선택과 포커스는 대개 파랑이라, 파랑을 쓰면 에이전트가 바꾼 셀과 헷갈립니다.
- 초안의 점선은 '아직 확정되지 않음'을 뜻합니다. 폐기는 더 쓰지 않는 데이터라 가장 흐리게 가라앉힙니다.
- 형태로 상태를 구분하는 방식은 axon의 '상태의 형태 문법'을 따랐습니다.

## 글꼴과 크기 (결정)

### 서체

| 쓰는 곳                                                    | 서체                                | 적용                                                                                                   |
| ---------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 본문, UI, 그리드                                           | Pretendard Variable 1.3.9 (SIL OFL) | npm `pretendard`의 dynamic subset woff2를 직접 제공합니다. 굵기는 400, 500, 600, 700만 씁니다          |
| 그리드 셀, 숫자·날짜 입력창                                | Pretendard + 고정폭 숫자            | `font-variant-numeric: tabular-nums;` 숫자 모양은 Pretendard 그대로입니다                              |
| 영문과 숫자가 섞인 코드 칸, 그 코드를 고르거나 입력하는 칸 | Pretendard + 고정폭 숫자 + 빗금 0   | `font-variant-numeric: tabular-nums; font-feature-settings: "zero" 1;`                                 |
| 메시지 미리 보기, 로그, 화면 ID 줄                         | D2Coding 1.3.2 (SIL OFL)            | npm `d2coding`의 `fonts/d2coding-full.woff2`(1.48MB)를 직접 제공합니다. 쓰는 화면에서만 내려받습니다   |
| 로그인 화면 제목, MMD 글자 로고                            | LG EI Text                          | 글꼴 파일은 LG 자산이라 공개 저장소에 넣지 않고 회사 PC에서 추가합니다. LG EI Headline은 쓰지 않습니다 |

글꼴 순서

- 기본: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 고정폭: `D2Coding, Consolas, "Malgun Gothic", monospace`
- 브랜드: `"LG EI Text", "Pretendard Variable", Pretendard, "Malgun Gothic", sans-serif`

근거

- 숫자 전용 글꼴은 따로 두지 않습니다. 모든 셀은 `tabular-nums`로 숫자 폭만 맞추고 숫자 모양은 Pretendard 그대로 둡니다. 고정폭 글꼴(예: IBM Plex Mono)은 더 기계적으로 보이고 그리드 폭이 넓어집니다.
- 0과 O는 `zero`(빗금 0)로 구분합니다. 영문과 숫자가 섞인 코드 칸과 선택 상자의 코드 부분에만 켭니다.

  | 코드      | 형식               | 빗금 0                         |
  | --------- | ------------------ | ------------------------------ |
  | 공정 코드 | 숫자만             | 끔                             |
  | Route     | 영문 대문자 + 숫자 | 켬                             |
  | P/N       | 영문 + 숫자        | 켬                             |
  | 공장      | `P9`, `P8`         | 켬                             |
  | Shop      | `P9T`, `P9C`       | 켬                             |
  | LOT       | 확인 전            | 형식을 확인한 뒤 같은 기준으로 |

- 수량, 기준값, 날짜, 시각에는 O가 나올 일이 없어 빗금 0이 장식만 되고 화면이 지저분해집니다.
- 코드가 대문자뿐이라 1과 I는 Pretendard 기본 모양으로 구분됩니다(1에 깃발이 있음). 그래서 `cv05`(꼬리 있는 l)와 `cv08`(세리프 있는 I)은 쓰지 않습니다. 소문자가 들어가는 코드가 확인되면 그 코드에만 더합니다.
- 고정폭 글꼴은 글자 칸이 세로로 맞아야 하는 곳에만 씁니다. D2Coding은 한글이 정확히 2칸이라 한글 값이 섞인 메시지도 열이 맞습니다. JetBrains Mono는 한글 글자가 없어 한글에서 정렬이 깨집니다.
- LG EI Text는 LG 전용 서체이고, MMD는 LG 계열사 시스템이라 쓸 수 있습니다(2026-11-20 확인). 서체로 브랜드를 드러내는 자리(로그인 화면 제목, 글자 로고)에만 씁니다. LG EI Headline은 LG 가이드상 캠페인·히어로용이라 쓰지 않습니다.
- LG EI Text에 한글 글자가 있는지와 Windows에서 작은 크기로 잘 보이는지는 공식 페이지에 없어 회사 PC에서 확인합니다. 한글 글자가 없으면 한글은 Pretendard로 표시됩니다.
- Pretendard와 D2Coding은 반입할 때 `docs/import-list.md`에 적습니다.

### 크기 조정: 모니터 보정과 글자 크기 설정

크기는 서로 다른 두 가지 이유로 바뀌며, 둘을 따로 둡니다.

| 축          | 정하는 방법                       | 목적                                                | 더하는 값      |
| ----------- | --------------------------------- | --------------------------------------------------- | -------------- |
| 모니터 보정 | 자동. 사용자에게 보이지 않습니다  | 넓은 모니터에서 1px이 작게 보이는 만큼 보정합니다   | 모든 글자 +1px |
| 글자 크기   | 사용자가 '보통'과 '크게'에서 고름 | 큰 글자가 필요한 사용자. 어느 모니터에서든 커집니다 | 모든 글자 +2px |

둘 다 적용되면 +3px입니다. 행과 컨트롤 높이도 함께 바뀝니다. 간격(4px 단위)은 바뀌지 않습니다.

| 항목                       | 기준 | 넓은 모니터 | 크게 | 넓은 모니터 + 크게 |
| -------------------------- | ---- | ----------- | ---- | ------------------ |
| 그리드 글자 (text-sm)      | 13px | 14px        | 15px | 16px               |
| 그리드 행 높이             | 28px | 30px        | 32px | 34px               |
| 컨트롤 높이 (버튼, 입력창) | 32px | 34px        | 36px | 38px               |
| 배지 높이                  | 20px | 22px        | 24px | 26px               |

모니터 보정

- 모니터 폭 `screen.width`(CSS px)가 2,200px 이상이면 넓은 모니터입니다. 창 폭이 아니라 모니터 폭을 봅니다. 창 크기를 바꾸거나 화면을 나눠 써도 바뀌지 않고, 창을 다른 모니터로 옮길 때만 다시 계산합니다.
- `<html>`에 `data-screen="wide"`를 붙이고, 크기 토큰을 그 값에 따라 바꿉니다.

| 기기                | 흔한 배율 | 모니터 폭     | 구분        | 1px 실제 크기                |
| ------------------- | --------- | ------------- | ----------- | ---------------------------- |
| LG 24" FHD          | 100%      | 1,920px       | 보통        | 0.277mm                      |
| LG gram 14"~17"     | 125~200%  | 1,280~2,048px | 보통        | 0.20~0.24mm (눈과 더 가까움) |
| LG 27" QHD          | 100%      | 2,560px       | 넓은 모니터 | 0.233mm                      |
| LG 27" 4K           | 150%      | 2,560px       | 넓은 모니터 | 0.233mm                      |
| LG 34" 울트라와이드 | 100%      | 3,440px       | 넓은 모니터 | 0.231mm                      |

27" QHD에서 13px은 3.0mm로, 24" FHD의 3.6mm보다 16% 작습니다. 보정한 14px은 3.3mm입니다.

글자 크기 설정

- 화면 설정에 '글자 크기: 보통 / 크게'로 둡니다. 기본은 '보통'이고, 사용자별로 저장합니다. 서버 목업의 '밀도: 표준 / 넓게'를 이 이름으로 바꿉니다. 이 설정을 찾는 사람은 '밀도'보다 '글자'라는 말을 먼저 찾습니다.
- `<html>`에 `data-text-size="large"`를 붙입니다.
- 브라우저 확대(Ctrl +)는 항상 동작해야 합니다. 크기는 토큰으로만 쓰고, 200% 확대에서도 내용이 잘리지 않아야 합니다(WCAG 1.4.4).

## 간격, 모서리, 테두리, 그림자 (결정)

값은 두 층 토큰으로 둡니다. 기본 단계는 숫자만 정하고, 화면과 컴포넌트는 쓰는 곳으로 이름 붙인 쓰임 토큰만 씁니다. CSS Modules에 px 숫자를 직접 쓰지 않고, 이 규칙은 stylelint로 막습니다('CSS 검사').

### 간격

기본 단계는 4px 단위 6단계입니다: `space-1` 4px, `space-2` 8px, `space-3` 12px, `space-4` 16px, `space-5` 24px, `space-6` 32px. 간격은 글자 크기 설정과 모니터 보정에 따라 바뀌지 않습니다.

| 쓰임 토큰                 | 값       | 쓰는 곳                                |
| ------------------------- | -------- | -------------------------------------- |
| gap-inline                | 4px      | 아이콘과 글자                          |
| gap-label                 | 4px      | 라벨과 입력창                          |
| pad-input-x               | 8px      | 입력창 안 좌우                         |
| pad-cell-x                | 8px      | 그리드 셀 안 좌우                      |
| pad-button-x              | 12px     | 버튼 안 좌우                           |
| gap-buttons               | 8px      | 같은 묶음의 버튼 사이                  |
| gap-field-x / gap-field-y | 12 / 8px | 조회 조건과 폼의 칸 사이 (가로 / 세로) |
| pad-panel                 | 12px     | 작업 패널 안: 조회 조건, 툴바, 상세 폼 |
| pad-float                 | 16px     | 떠 있는 상자 안: 다이얼로그, 토스트    |
| gap-panel                 | 12px     | 패널 사이                              |
| page-gutter               | 16px     | 화면 가장자리                          |
| pad-empty                 | 32px     | 빈 상태 안                             |

안쪽 간격은 바깥 간격보다 크지 않습니다. 관계가 가까운 것끼리 더 붙어 보이게 합니다.

### 모서리

| 토큰      | 값  | 쓰는 곳                                                                      |
| --------- | --- | ---------------------------------------------------------------------------- |
| (없음)    | 0   | 그리드 셀, 탭, 화면 가장자리에 붙은 패널                                     |
| radius-sm | 3px | 배지, 체크박스                                                               |
| radius-md | 4px | 한 줄짜리 컨트롤과 막대: 버튼, 입력창, 선택 상자, 메뉴 항목, 툴팁, 안내 배너 |
| radius-lg | 6px | 여러 요소를 담는 상자: 패널, 그리드 상자, 드롭다운, 다이얼로그, 토스트       |
| 원        | 50% | 점, 에이전트 고리                                                            |

- 알약형은 쓰지 않습니다. 모서리는 높이의 절반을 넘지 않습니다.
- 안쪽 요소의 모서리는 감싸는 요소보다 크지 않습니다.
- 사이드 메뉴의 활성 항목은 막대가 붙는 왼쪽 모서리를 0으로 둡니다.

### 테두리

| 굵기 | 쓰는 곳                                                                 |
| ---- | ----------------------------------------------------------------------- |
| 1px  | 구조: 패널 윤곽, 구분선, 그리드 선, 입력창, 배지                        |
| 2px  | 상태: 포커스, 열린 입력 칸, 편집 중인 셀, 현재 위치 막대, 에이전트 고리 |

| 색            | 쓰는 곳                                                               |
| ------------- | --------------------------------------------------------------------- |
| 구분선        | 패널 윤곽, 그리드 선                                                  |
| 강한 테두리   | 그리드 머리글 아래, 보조 버튼, 읽기 전용·비활성 칸, 떠 있는 상자 윤곽 |
| 입력창 테두리 | 편집할 수 있는 칸                                                     |
| 의미색        | 상태 배지, 오류 칸                                                    |

점선은 '아직 확정되지 않음'(초안)에만 씁니다. 빈 상태를 점선 상자로 그리지 않습니다.

### 그림자와 층

| 단계          | 쓰는 곳                                       | 라이트                                                                                | 다크                                              |
| ------------- | --------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 0 평면        | 패널, 조회 조건, 그리드, 도킹한 에이전트 패널 | 그림자 없음. 테두리로 구분                                                            | 같음                                              |
| 1 떠 있음     | 드롭다운, 메뉴, 툴팁, 토스트                  | 패널 면 + 강한 테두리 + `0 4px 16px rgb(17 18 20 / 0.1)`                              | 그림자 없음. `#282C2F` 면 + 강한 테두리           |
| 2 화면을 막음 | 다이얼로그, 확인 창                           | 패널 면 + 강한 테두리 + `0 12px 32px rgb(17 18 20 / 0.16)`, 막 `rgb(17 18 20 / 0.32)` | `#282C2F` 면 + 강한 테두리, 막 `rgb(0 0 0 / 0.5)` |

- 다크에서는 그림자가 보이지 않아 면의 밝기로 높이를 나타냅니다. 떠 있는 면을 `#282C2F`(L 0.29)로 둔 것은 가장 밝은 바탕인 그리드 머리글 단계(bg-sunken, `#1E2124`)보다 밝아야 해서입니다. 그 값을 쓰면 그리드 머리글이나 읽기 전용 칸 위에서 열린 드롭다운이 바탕에 묻힙니다.
- 막은 사이드 메뉴까지 앱 전체를 덮습니다.
- 층 순서(z-index): 기본 0, 고정 머리글 10, 도킹 패널 20, 다이얼로그·서랍 30, 드롭다운·메뉴 40, 토스트 50, 툴팁 60. 드롭다운은 다이얼로그 안의 선택 상자에서도 열리므로 다이얼로그 위에, 툴팁은 다이얼로그와 토스트 안의 버튼에도 뜨므로 맨 위에 둡니다. 다이얼로그가 열려 있으면 뒤 화면을 누를 수 없어 뒤의 드롭다운이 다이얼로그 위로 올라오는 일은 없습니다.

### 선택 표시

| 표시     | 뜻               | 쓰는 곳                                                                        |
| -------- | ---------------- | ------------------------------------------------------------------------------ |
| 막대 2px | 지금 있는 곳     | 사이드 메뉴(왼쪽, 브랜드 레드), 탭(아래, 본문색), 그리드 현재 행(왼쪽, 본문색) |
| 체크     | 고른 값          | 드롭다운 항목, 목록                                                            |
| 면       | 지금 가리키는 것 | 마우스 올림, 키보드로 이동 중인 항목                                           |
| 채운 면  | 고른 쪽          | 세그먼트 버튼(주요 버튼 면)                                                    |

- 드롭다운 항목에는 막대를 쓰지 않습니다. 막대를 쓰면 '현재 위치'와 '고른 값'이 같아 보입니다. Carbon은 드롭다운에서 고른 항목을 선택 면과 체크로, Fluent 2와 Primer는 메뉴의 현재 페이지를 별도 표시로 나타냅니다.
- 로고의 빨간 띠와 활성 메뉴의 빨간 띠는 같은 세로선 위에 둡니다. 둘 다 안쪽 2px 막대이고 왼쪽 위치가 같습니다. 탭 밑줄과 그리드 막대에는 빨강을 쓰지 않습니다.

### 입력 칸 상태

선택 상자와 입력창은 같은 규칙을 씁니다.

| 상태         | 면        | 테두리                                                            | 글자                                  |
| ------------ | --------- | ----------------------------------------------------------------- | ------------------------------------- |
| 기본         | 패널      | 입력창 테두리 1px                                                 | 본문                                  |
| 마우스 올림  | 패널      | 보조 글자색 1px                                                   | 본문                                  |
| 열림, 포커스 | 패널      | 본문색 2px, 안쪽으로 (`outline: 2px solid; outline-offset: -1px`) | 본문. 선택 상자는 화살표가 뒤집힙니다 |
| 오류         | 패널      | negative 1px, 포커스 때 negative 2px                              | 칸 아래에 negative 안내 문구          |
| 읽기 전용    | bg-sunken | 강한 테두리                                                       | 본문                                  |
| 비활성       | 없음      | 강한 테두리                                                       | 비활성 글자                           |

- 버튼, 탭, 링크의 키보드 포커스는 바깥 2px 본문색 링(`outline-offset: 2px`)입니다. 그리드 셀의 포커스와 편집 중인 셀은 안쪽 2px입니다.
- 포커스는 `outline`으로 그립니다. `box-shadow`는 Windows 고대비 모드에서 사라집니다.
- 필수 표시 `*`는 보조 글자색입니다. 빨강은 오류와 반려에만 씁니다.
- 코드와 이름을 함께 보일 때는 "PN-2001 · 개발 모델"처럼 가운뎃점으로 나누고 이름은 보조 글자색으로 씁니다. 코드에 하이픈이 들어 있어 하이픈으로 나누면 헷갈립니다.

### 상호작용 상태

누를 수 있는 모든 요소(버튼, 메뉴 항목, 탭, 드롭다운 항목, 그리드 행, 세그먼트, 체크박스)가 같은 규칙을 씁니다. 상태가 바뀌어도 크기, 모서리, 테두리 굵기, 글자 굵기는 바뀌지 않고 면과 글자색만 바뀝니다.

| 상태               | 면이 있는 것 (보조 버튼 등)                 | 면이 없는 것 (고스트, 메뉴·드롭다운 항목, 그리드 행) | 주요 면 (주요 버튼, 고른 세그먼트, 체크한 상자) |
| ------------------ | ------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------- |
| 마우스 올림        | 면 위에 마우스 올림 면(`--bg-hover`)을 얹음 | 마우스 올림 면. 고스트와 메뉴는 글자도 본문색        | `--primary-hover`                               |
| 누름               | 누름 면(`--bg-press`)을 얹음                | 누름 면. 그리드 행은 누름 표시 없음                  | `--primary-press`                               |
| 선택 + 마우스 올림 |                                             | 선택 표시 위에 마우스 올림 면을 한 겹 더             | `--primary-hover`                               |
| 비활성             | 면 없음, 강한 테두리, 비활성 글자           | 비활성 글자                                          | 비활성 면(`--bg-disabled`), 비활성 글자         |
| 처리 중            | 면 그대로, 스피너                           | 면 그대로, 스피너                                    | 면 그대로, 스피너                               |

- 투명도 면은 바탕이 무엇이든 한 단계씩 진해집니다: 마우스 올림 0.05 → 누름 0.09 → 선택 0.13(다크 0.04 → 0.07 → 0.10).
- 글자만 있는 탭은 마우스 올림 때 글자색만 본문색으로 바뀝니다. 막대는 현재 위치에만 씁니다.
- 비활성 글자는 약 3:1로 안내 글자(약 5:1)보다 한 단계 흐립니다. WCAG는 비활성 요소를 대비 기준에서 빼지만, 무엇인지는 읽혀야 합니다. 투명도(opacity)로 흐리게 하지 않습니다. 바탕이 비쳐 다크에서 탁해지고, 입력 칸의 비활성과 모양이 달라집니다.
- 비활성 버튼은 `disabled` 대신 `aria-disabled="true"`로 두어 키보드 포커스를 남기고, 툴팁으로 이유를 알립니다(예: `저장할 변경이 없습니다`). 마우스 올림 반응은 없습니다.
- 처리 중은 비활성과 다르게 보여야 합니다. 면을 그대로 두고 아이콘 자리에 스피너를 돌립니다. 아이콘이 없으면 글자 앞에 붙입니다. 글자는 바꾸지 않습니다. `aria-busy="true"`이고, 처리 중에 다시 눌러도 요청을 보내지 않습니다. 다시 누를 수 없게 하는 것은 누른 순간부터, 스피너는 0.3초 뒤부터입니다('모션'의 기다림).
- 커서는 버튼과 메뉴도 기본 화살표이고, 링크만 손가락입니다. 상태 면이 이미 반응을 보여 줍니다.
- 상태 색은 `--duration-fast`(80ms) 동안 바뀝니다('모션').
- 투명도 면은 면 위에 한 겹 얹습니다. 면이 없는 요소는 `background-color`로, 면이 있는 요소(보조 버튼)는 면 위에 겹친 층(`::before`)의 `background-color`로 그려 전환이 되게 합니다. `background-image`는 전환되지 않습니다.

### 컨트롤 크기

| 크기 | 높이                                   | 안 좌우 (버튼) | 쓰는 곳                                                                                                                |
| ---- | -------------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 기본 | 컨트롤 높이 (`--control-height`, 32px) | 12px           | 화면에 놓이는 모든 컨트롤: 조회 조건, 툴바, 폼, 다이얼로그 버튼, 사이드 메뉴 항목                                      |
| 작게 | 행 높이 (`--control-height-sm`, 28px)  | 8px            | 행 높이 상자 안에 들어가는 컨트롤만: 그리드 셀 편집, 토스트·배너 안 동작, 드롭다운 안 검색 칸, 사이드 메뉴의 화면 설정 |

- 두 단계 모두 크기 조정을 따라 커지고, 글자는 같은 text-sm입니다. 큰 버튼은 두지 않습니다.
- 같은 줄에 놓인 컨트롤은 높이를 섞지 않습니다. 조회 조건의 입력 칸과 조회 버튼은 같은 높이입니다.
- 아이콘만 있는 버튼은 정사각형입니다(32×32, 작게 28×28).
- 28px도 WCAG 최소 대상 크기 24px(2.5.8)을 넘습니다.

### 아이콘 (결정)

Fluent UI System Icons(Microsoft, MIT)의 Regular를 씁니다. npm `@fluentui/svg-icons`에서 화면에 쓰는 아이콘만 `frontend/scripts/build-icons.mjs`가 골라 `src/shared/icons/icons.generated.ts`로 만들고, 화면은 `shared/icons/Icon` 컴포넌트로만 씁니다(`<Icon name="search" />`).

| 크기      | 토큰             | 그림 (글자 크기 보통 / 크게) | 쓰는 곳                                    |
| --------- | ---------------- | ---------------------------- | ------------------------------------------ |
| sm        | `--icon-size-sm` | 12px / 16px                  | 배지, 그리드 머리글의 정렬·필터            |
| md (기본) | `--icon-size-md` | 16px / 20px                  | 버튼, 입력 칸, 메뉴, 행 동작, 토스트, 배너 |
| lg        | `--icon-size-lg` | 24px / 28px                  | 빈 상태, 확인 창                           |

- 아이콘은 크기마다 따로 그려진 그림이라 그 크기에서 선이 픽셀에 맞습니다. 그래서 글자처럼 1px씩 키우지 않고, 글자 크기 '크게'에서 한 단계 큰 그림으로 건너뜁니다. 모니터 보정(+1px)으로는 바꾸지 않습니다. 17px처럼 그림 크기가 아닌 값으로 그리면 선이 픽셀 사이에 걸려 흐려집니다.
- 색은 글자색(`currentColor`)을 따릅니다. 버튼 안 아이콘은 버튼 글자색, 혼자 있는 아이콘(행 동작, 입력 칸 끝의 화살표·달력)은 보조 글자색입니다.
- 의미색은 뜻이 있을 때만 씁니다: 토스트의 성공(positive)·오류(negative), 주의 배너의 삼각형(warning). 브랜드 레드는 아이콘에 쓰지 않습니다.
- 버튼은 글자가 먼저이고 아이콘은 앞에 붙습니다(사이 4px). 아이콘을 붙이는 버튼은 '버튼'을 따릅니다. 아이콘만 있는 버튼은 뜻이 분명한 것(더 보기, 닫기, 새로 고침)만 쓰고, 정사각형에 `label`(`aria-label`)과 툴팁을 답니다.
- 정렬하지 않은 머리글에는 아이콘을 두지 않고, 정렬한 열에만 화살표(`arrow-up`, `arrow-down`)를 둡니다.
- 에이전트는 아이콘 대신 2px 고리를 씁니다.
- 한 개념에 한 아이콘입니다. 아래 표에 없는 아이콘이 필요하면 스크립트의 목록과 이 표에 함께 더하고 `npm run icons`를 실행합니다.

근거

- 배율 100% 모니터(LG 24" FHD, 27" QHD)에서 16px 아이콘을 비교했습니다. Lucide와 Tabler는 24px 격자의 2px 선을 16px로 줄여 선이 반 픽셀씩 번졌고, Fluent와 Carbon은 16px 그림이라 선이 픽셀에 맞았습니다. SVG는 벡터라 깨지지는 않지만, 화면에 찍을 때 픽셀 사이에 걸린 선은 회색으로 번집니다.
- Fluent는 Windows 11과 Office의 아이콘이라 사용자가 매일 보는 모양이고, 1px 선이 Pretendard 13px 글자 굵기와 비슷합니다. Carbon은 끝이 각져 IBM 제품의 인상이 강했습니다.
- `@fluentui/react-icons`는 181MB라 반입이 무겁고, 화면에서 쓰는 아이콘은 40여 개라 SVG 원본(`@fluentui/svg-icons`, 개발 의존성)에서 쓰는 것만 골라 넣습니다. 앱에 들어가는 크기는 약 17KB(gzip)입니다.

## 표기와 문구 (결정)

화면에 날짜, 시각, 숫자, 빈 값을 쓸 때는 `frontend/src/shared/format/format.ts`의 함수(`formatDate`, `formatDateTime`, `formatNumber` 등)만 씁니다. 직접 문자열로 만들지 않습니다.

원칙

- 값은 있는 그대로: 숫자를 줄이거나(1.2K) 반올림해 보이지 않고, 자리를 자르지 않습니다. 잘린 숫자는 틀린 숫자입니다(Precision).
- 같은 것은 늘 같은 모양: 날짜, 빈 값, 단위, 용어를 화면마다 바꾸지 않습니다(Clarity).
- 짧고 담담하게: 무엇이 일어났고 무엇을 하면 되는지만 씁니다. 느낌표, 사과, 꾸밈말을 쓰지 않습니다(Calm).

### 날짜와 시각

| 쓰는 곳   | 모양                      | 함수                     | 규칙                                                                                       |
| --------- | ------------------------- | ------------------------ | ------------------------------------------------------------------------------------------ |
| 날짜      | `2026-11-20`              | `formatDate`             | 월과 일은 두 자리                                                                          |
| 일시      | `2026-11-20 09:12`        | `formatDateTime`         | 24시간제. 오전·오후, 요일을 쓰지 않습니다                                                  |
| 초까지    | `2026-11-20 09:12:05`     | `formatDateTimeSeconds`  | 변경 이력, 메시지 이력, 로그처럼 1분 안의 순서가 중요한 곳에만                             |
| 기간      | `2026-11-01 ~ 2026-11-20` | `formatDateRange`        | 물결표 앞뒤에 한 칸, 앞뒤 모두 전체 날짜                                                   |
| 지난 시간 | `3분 전`                  | (에이전트 화면에서 정함) | 그리드에는 쓰지 않습니다. 에이전트 대화와 알림에서만 쓰고, 툴팁으로 정확한 일시를 보입니다 |

- 하이픈 형식(ISO 8601)은 글자 순서대로 정렬하면 날짜 순서가 되고, DB·로그·메시지 미리 보기와 같은 모양입니다. 점 형식(`2026.11.20`)은 소수가 있는 값 옆에서 숫자처럼 보이고 엑셀에서 숫자로 바뀔 수 있어 쓰지 않습니다. 빗금 형식은 나라마다 월/일 순서가 달라 쓰지 않습니다.
- 입력 칸도 같은 모양으로 보이고 같은 모양으로 입력받습니다.
- 시간대는 회사에서 정합니다. 한국 시각으로 고정할지, 공장 현지 시각을 쓸지는 해외 공장 데이터가 섞이는지 확인한 뒤 정합니다. 그때까지 함수는 브라우저의 시간대로 씁니다.

### 숫자

| 종류           | 이렇게                 | 쓰지 않음                |
| -------------- | ---------------------- | ------------------------ |
| 수량·값        | `1,280` · `1,280.0`    | `1280`, `1.28K`, `1.3천` |
| 큰 수          | `12,345,678`           | `1,234만`, `12.3M`       |
| 소수 자릿수    | `96.40` (항목이 2자리) | `96.4`                   |
| 코드·번호·연도 | `1010` · `2026`        | `1,010`, `2,026`         |
| 음수           | `-12.5`                | `(12.5)`, 빨간 글자      |
| 백분율         | `96.40%`               | `96.40 %`, `0.964`       |
| 0              | `0`                    | `–`, 빈칸                |
| 문장 안 단위   | `30초` · `4건` · `2행` | `30 초`                  |

- 소수 자릿수는 항목 정의(명세)를 따르고 끝의 0을 지우지 않습니다: `formatNumber(value, 자릿수)`.
- 그리드에서 단위는 머리글(`수량 (EA)`)에 둡니다. 행마다 단위가 다르면 단위 열을 둡니다. 칸마다 단위를 붙이지 않습니다.
- 숫자 입력 칸은 편집할 때 쉼표 없이 보이고, 칸을 벗어나면 쉼표를 넣습니다.
- 음수를 빨강으로 쓰지 않습니다. 빨강은 오류와 반려에만 씁니다.

### 빈 값

- 값이 없으면(null, 빈 문자열) `–`(en dash)를 안내 글자색으로 씁니다: `EMPTY`, `formatText`. 숫자 열에서는 오른쪽 정렬입니다.
- 0은 `0`입니다. 빈칸으로 두지 않습니다. 빈칸은 값이 없는 것인지, 아직 못 불러온 것인지, 화면이 잘못된 것인지 알 수 없습니다.
- `없음` 같은 글자를 쓰지 않습니다. 그리드가 시끄럽고 실제 값과 헷갈립니다.

### 넘치는 글자와 툴팁

- 코드, 숫자, 날짜 열은 자르지 않습니다. 열 폭을 내용에 맞춥니다.
- 이름과 비고처럼 긴 글만 끝에서 자르고(`…`), 잘렸을 때만 마우스를 올리면 툴팁으로 전체를 보입니다. 전체는 상세 패널에서도 봅니다.
- 버튼과 라벨은 자르지 않습니다. 넘치면 배치를 바꿉니다.
- 툴팁 모양: 떠 있는 면(1단계), 강한 테두리, 모서리 4px, text-xs, 안쪽 4px 8px, 최대 폭 320px. 화살표 꼬리는 두지 않고 대상 아래 4px에 둡니다.
- 툴팁을 쓰는 곳: 아이콘만 있는 버튼의 이름(단축키가 있으면 함께), 비활성 버튼의 이유, 잘린 글자의 전체, 편집 상태 표시(`+ • −`)와 약어 머리글의 뜻.
- 툴팁에는 누를 것을 넣지 않고, 툴팁에만 있는 정보를 두지 않습니다.
- 키보드 포커스 때도 보이고, Esc로 닫히며, 툴팁 위로 마우스를 옮겨도 사라지지 않습니다(WCAG 1.4.13). 나타나는 시간은 '모션'을 따릅니다.
- 아래에 자리가 없으면 대상 위에 뜨고, 창 밖으로 나가지 않게 안으로 옮깁니다. 대상이 스크롤되거나 창 크기가 바뀌면 닫힙니다. 손가락 터치에는 뜨지 않습니다.
- 코드는 `frontend/src/shared/ui/Tooltip.tsx`입니다. 버튼에는 `Button`의 `label`(아이콘만 있는 버튼)과 `disabledReason`(비활성 이유)을 쓰고, 그 밖의 대상(잘린 글자, 편집 상태 표시)은 `<Tooltip content="신규">`로 감쌉니다. 대상은 키보드로 포커스를 받을 수 있어야 합니다.

## 모션 (결정)

움직임은 화면이 바뀐 것을 알려 줄 때만 씁니다. 장식용 모션은 두지 않습니다(컨셉).

| 토큰                | 값                           | 쓰는 곳                                                                                  |
| ------------------- | ---------------------------- | ---------------------------------------------------------------------------------------- |
| `--duration-fast`   | 80ms                         | 상태 색: 마우스 올림, 누름, 체크, 그리드 행                                              |
| `--duration-normal` | 150ms                        | 떠 있는 것이 나타나고 사라짐: 드롭다운, 메뉴, 툴팁, 토스트, 확인 창, 막. 조회 중 행 흐림 |
| `--duration-slow`   | 200ms                        | 서랍, 들어오는 패널(에이전트 패널, 다시 펼친 메뉴)                                       |
| `--duration-spin`   | 800ms                        | 스피너 한 바퀴                                                                           |
| `--ease-out`        | `cubic-bezier(0.2, 0, 0, 1)` | 나타날 때, 상태 색                                                                       |
| `--ease-in`         | `cubic-bezier(0.4, 0, 1, 1)` | 사라질 때                                                                                |

움직이는 것

- 상태 색은 80ms 동안 바뀝니다. 그리드 행을 훑을 때 깜빡이지 않습니다.
- 떠 있는 것은 150ms 동안 옅게 나타나고 사라집니다(페이드). 자리를 옮기거나 커지지 않습니다.
- 서랍은 200ms 동안 왼쪽에서 밀려 나옵니다. 어디서 왔는지가 뜻이기 때문입니다.
- 자리를 옮기거나 커지는 효과, 튕김, 반짝임(skeleton shimmer)은 쓰지 않습니다.

레이아웃이 바뀔 때

- 메뉴 접기, 에이전트 패널 열기, 구간 바뀜은 자리가 한 번에 바뀌고, 들어오는 패널의 내용만 200ms 동안 밀려 들어옵니다. 그리드는 한 번만 다시 배치됩니다.
- 본문 폭을 움직이며 바꾸지 않습니다. 그 동안 그리드가 매 프레임 다시 배치되어 열 너비가 출렁이고, 큰 데이터에서는 끊깁니다.
- 행 추가·삭제, 정렬, 탭 바꿈은 움직이지 않습니다.

기다림

- 0.3초가 넘을 때만 로딩 표시를 합니다. 한번 보이면 0.5초는 둡니다. 빨리 끝나는 조회에서 표시가 깜빡이지 않게 하기 위해서입니다.
- 조회 중에는 기존 행을 흐리게 남기고(위치를 잃지 않게) 그리드 가운데에 스피너와 `조회 중`을 둡니다.
- 처리 중인 버튼은 누른 순간부터 다시 누를 수 없고, 스피너는 0.3초 뒤에 보입니다. 스피너는 한 바퀴 0.8초입니다.
- 0.3초와 0.5초 규칙은 `shared/ui/useDelayedBusy`가, 스피너는 `shared/ui/Spinner`가 그립니다. 버튼은 `busy`만 주면 됩니다.

툴팁

- 마우스를 올리고 0.5초 뒤에 나타납니다. 지나가기만 하는 마우스에는 뜨지 않습니다.
- 툴팁이 떠 있는 동안 옆 요소로 옮기면 바로 바뀝니다.
- 키보드 포커스는 바로 보입니다. 마우스가 떠날 때는 0.1초 기다려 툴팁 위로 옮길 수 있게 합니다.

동작 줄이기

- OS의 '동작 줄이기'(`prefers-reduced-motion: reduce`)가 켜져 있으면 밀려 나오는 움직임을 없앱니다. 서랍과 들어오는 패널은 페이드만 하거나 바로 나타납니다.
- 스피너는 기다림을 알리는 표시라 계속 돕니다.

에이전트가 값을 바꿀 때의 표시는 에이전트 단계에서 정합니다.

## 토큰 파일과 Storybook (적용)

위의 값은 `frontend/scripts/build-tokens.mjs`가 원본입니다. `npm run tokens`를 실행하면 `frontend/src/shared/styles/tokens.css`와 대비 검사 결과 `frontend/tokens-report.md`를 만듭니다.

- `tokens.css`는 손으로 고치지 않습니다. 값을 바꿀 때는 이 문서와 스크립트를 함께 고치고 `npm run tokens`를 실행합니다. `npm run build`는 두 파일이 맞는지 먼저 검사합니다.
- 스크립트는 대비를 검사하고, 기준에 못 미치면 실패합니다. 모든 글자는 다섯 바탕(메뉴, 본문 바탕, 패널, 그리드 머리글 단계, 떠 있는 면) 위에서 4.5:1 이상, 본문과 보조 글자는 메뉴, 본문 바탕, 패널 위에서 12:1과 7:1 이상, 의미색은 패널과 자기 옅은 면 위에서 4.5:1 이상, 입력창 테두리와 활성 메뉴 표시선은 메뉴를 포함한 바탕 위에서 3:1 이상입니다. 비활성 글자는 2.5:1 이상이면서 안내 글자보다 흐려야 하고, 주요 버튼 글자는 마우스 올림과 누름에서도 4.5:1 이상, 상태 면은 마우스 올림 < 누름 < 선택 순서로 한 단계씩 진해져야 합니다. 면 순서도 검사합니다. 메뉴 < 본문 바탕 < 패널 순서로 밝고, 이웃한 면 사이와 그리드 머리글 단계(bg-sunken)와 본문 바탕·패널 사이는 OKLCH 명도가 0.015 이상 차이 나야 합니다. 다크의 떠 있는 면은 bg-sunken보다 밝아야 합니다. 면을 같은 값으로 만들어 구분이 사라지는 것을 막으려는 검사입니다.
- 테마는 OS 설정을 따르고, 사용자가 고르면 `<html data-theme="light">` 또는 `"dark"`로 고정합니다. 글자 크기 '크게'는 `data-text-size="large"`, 넓은 모니터는 `data-screen="wide"`입니다. 넓은 모니터는 `shared/styles/display.ts`의 `watchScreenSize()`가 붙입니다.
- Storybook의 '기초' 페이지에서 색, 상태 표시, 글꼴과 크기, 간격, 모서리와 테두리, 그림자와 층, 선택과 포커스, 상호작용 상태, 아이콘, 표기와 문구, 화면 골격, 모션을 봅니다. 도구 막대에서 테마, 글자 크기, 모니터를 바꿉니다. 이 페이지의 그림은 규칙을 보여 주는 것이라 화면에서 가져다 쓰지 않습니다.
- '컴포넌트' 페이지에서 화면에 가져다 쓰는 컴포넌트(버튼, 입력창과 선택 상자, 체크박스·라디오·세그먼트, 알림, 화면 틀)의 종류, 상태, 놓는 자리를 봅니다. '직접 바꿔 보기'에서 속성을 바꿔 볼 수 있습니다.

### CSS 검사 (적용)

`npm run lint:css`(stylelint)가 `src`의 CSS를 검사하고, `npm run build`가 먼저 실행합니다. 규칙은 `frontend/stylelint.config.mjs`에 있습니다.

| 막는 것                                                                                          | 대신 쓰는 것                                                                                          |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 색 값: `#fff`, `red`, `rgb()`, `oklch()`, `color-mix()`                                          | 색 토큰 (`--text`, `--bg-hover` 등)                                                                   |
| 길이 단위: `px`, `rem`, `em`, `ch` 등                                                            | 간격·크기 토큰. `0`, `%`, `fr`, `vw`, `vh`는 씁니다                                                   |
| `transition`, `animation`의 시간 값 (`150ms`)                                                    | 모션 토큰 (`--duration-normal`)                                                                       |
| `font` 줄임 속성                                                                                 | `font-family`, `font-size`, `font-weight`, `line-height`를 따로 씁니다                                |
| 토큰이 아닌 `font-size`, `font-weight`, `font-family`, `line-height`, `border-radius`, `z-index` | `--text-*`, `--weight-*`, `--font-*`, `--leading-*`(또는 `1`), `--radius-*`(또는 `0`, `50%`), `--z-*` |
| `!important`                                                                                     | 선택자를 바로 씁니다                                                                                  |

- 화면 배치 구간(1440, 1024, 900, 640, 높이 560)은 CSS 변수를 쓸 수 없어 `@media`의 폭·높이와 `@container`에는 숫자를 씁니다.
- 검사하지 않는 파일: `tokens.css`(토큰을 정의함), `fonts.css`(글꼴 선언), '기초' 스토리의 그림(`shared/styles/foundations/`).
- 검사를 끄는 주석(`stylelint-disable`)을 쓰지 않습니다. 필요한 값이 토큰에 없으면 이 문서와 `build-tokens.mjs`에 토큰을 더합니다. 상용 그리드 테마처럼 바깥 값을 옮겨야 하는 파일은 그때 `ignoreFiles`에 이유와 함께 더합니다.
- TS 코드(인라인 `style`, 상수)에 쓴 색 값은 stylelint가 보지 못합니다. `npm test`의 `shared/ui/boundaries.test.ts`가 '기초' 스토리와 테스트를 뺀 코드에서 막습니다.

### 화면 머리

- 제목은 text-xl Bold입니다. 바로 아래 ID 줄은 D2Coding text-xs 안내 글자로 `PANEL_TPFOPOLICY · 레거시 SIC01061 · 화면 ID process.panelTpfopolicy`처럼 가운뎃점으로 나눕니다.
- 오른쪽에는 에이전트 버튼(고스트, 앞에 에이전트 고리)을 둡니다. 에이전트 패널의 자리와 폭은 '화면 골격'을, 내용은 에이전트 단계에서 정합니다.
- 메뉴가 접혀 있으면 제목 왼쪽에 메뉴 버튼(고스트, 아이콘만)을 둡니다.

### 탭

- 높이는 컨트롤, 탭 사이는 16px, 아래에 구분선을 둡니다. 모서리는 0입니다.
- 활성 탭은 본문색 SemiBold와 아래 2px 본문색 막대, 나머지는 보조 글자 Medium입니다.
- 탭을 바꿔도 앞 탭에서 고른 조회 조건은 다음 탭의 맥락 칸으로 넘깁니다.
- 탭마다 조회 조건과 작업 영역이 따로 있습니다. ←→로 옮깁니다. 저장하지 않은 변경이 있으면 확인 창을 띄운 뒤 바꿉니다('확인 창을 띄우는 때').
- 코드: `<Tabs label="Route" items={[{ id: "route", label: "Route" }, ...]} selected={tab} onChange={setTab}>{(id) => ...}</Tabs>` (`shared/ui/Tabs.tsx`)

### 안내 배너

- 경고: warning-soft 면, 앞에 warning 삼각형, 본문색 글자. 데모 안내가 여기에 해당합니다.
- 일반 안내: bg-sunken 면, 앞에 안내 글자색 정보 아이콘. 정보용 파랑을 쓰지 않습니다.
- 높이는 최소 컨트롤, 안 여백 위아래 4px·좌우 12px, 모서리 4px입니다.
- 화면에 대해 늘 알아야 할 것만 둡니다. 닫지 않습니다. 일이 끝난 결과는 토스트로, 오류는 일이 일어난 자리에 보입니다.
- 코드: `<Banner tone="warning">데모 데이터입니다. 저장해도 실제 MMD에는 반영되지 않습니다.</Banner>` (`shared/ui/Banner.tsx`)

### 조회 조건

- 패널 면(그리드와 같음), 구분선, 모서리 6px, 안 여백 12px입니다. 칸 사이는 가로 12px, 세로 8px입니다. 본문 바탕보다 밝아서 그리드와 나란한 판으로 보입니다.
- 늘 펼쳐 둡니다. 접기 버튼과 요약 줄을 두지 않습니다. 무엇으로 조회한 결과인지 늘 보이고, 조건을 바꾸려고 펼칠 일이 없습니다. 칸은 꼭 필요한 조건만 두고, 덜 쓰는 조건은 그리드의 열 필터로 옮겨 조회 조건이 되도록 한 줄에 들게 합니다.
- 라벨은 칸 위 4px에 둡니다(상세 폼과 같음). 라벨을 왼쪽에 두면 라벨이 앞 칸과 뒤 칸 사이에 떠서 어느 칸의 라벨인지 헷갈리고, 줄이 넘어가면 칸이 세로로 맞지 않습니다. 높이는 약 21px(그리드 한 행보다 작음) 더 듭니다.
- 칸 너비는 150~220px(`--query-field-min-width`~`--query-field-max-width`)에서 내용에 맞춥니다.
- 버튼은 칸 줄에 맞춥니다(라벨 줄 아래). 칸에서 Enter를 누르면 조회합니다. 조회 조건을 `<form>`으로 감싸고 조회 버튼을 `type="submit"`으로 둡니다.
- 비워도 되는 선택 상자는 목록 맨 위의 '전체'로 비웁니다(아래 '입력창과 선택 상자').
- 코드: `<QueryBar onSearch={search} onReset={reset} busy={query.isFetching}>{칸}</QueryBar>` (`shared/ui/QueryBar.tsx`). 조회·초기화 버튼, Enter로 조회, 칸 폭, 본문 640px 미만에서 한 줄에 하나는 QueryBar가 맡습니다.
- 조회(주요, 앞에 검색 아이콘)와 초기화(보조, 앞에 되돌리기 아이콘)는 마지막 칸 바로 뒤에 둡니다. 넓은 화면에서 버튼을 오른쪽 끝으로 보내지 않습니다.
- 연쇄 선택: 앞 칸을 고르기 전 다음 칸은 비활성이고, 칸에 이유를 보입니다(`공장을 먼저 선택`). 앞 칸을 바꾸면 뒤 칸을 비웁니다.
- 맥락 칸: 앞 탭에서 넘어온 값은 읽기 전용 칸으로 보여 줍니다.
- 필수 표시 `*`는 보조 글자색입니다. 값을 빠뜨리고 조회하면 그 칸만 오류 상태가 됩니다.

### 입력창과 선택 상자

- 상태는 '입력 칸 상태' 표를 따릅니다. 높이는 컨트롤, 안 좌우 8px, 모서리 4px입니다.
- 코드와 이름은 `PN-2001 · 개발 모델`로 보입니다. 이름은 보조 글자색이고, 빗금 0(`zero`)은 코드 부분에만 켭니다.
- 열린 목록은 떠 있음 1단계입니다. 안 여백 4px, 항목 높이는 행 높이, 항목 모서리 4px입니다.
- 목록에서 고른 항목은 앞에 체크, 키보드로 이동 중인 항목은 마우스 올림 면입니다. 항목 오른쪽 끝에 보조 정보(구분, 사용 안 함)를 text-xs 안내 글자로 붙일 수 있습니다.
- 항목이 15개를 넘으면 목록 위에 검색 칸을 둡니다(P/N처럼 값이 많은 경우). 검색 칸은 작은 컨트롤(행 높이)이고 앞에 검색 아이콘, 자리 표시 글자는 `코드나 이름으로 검색`입니다. 코드와 이름 어디에 들어 있어도 거르고, 맞는 항목이 없으면 `검색 결과가 없습니다.`를 보입니다.
- 라벨은 칸 위 4px, text-xs Medium 보조 글자입니다. 조회 조건과 상세 폼 모두 같습니다.
- 오류 문구는 칸 아래 text-xs negative로 `Route 이름을 입력하세요.`, `공장을 선택하세요.`처럼 씁니다.
- 고르지 않은 칸은 자리 표시 글자 `선택`을 안내 글자색으로 보입니다.
- 비워도 되는 선택 상자는 목록 맨 위에 '조건 없음' 항목을 두고 아래에 구분선을 긋습니다. 조회 조건은 `전체`, 상세 폼은 `없음`입니다. 고르면 칸에 그 글자가 본문색으로 남아 지금 조건이 보입니다. 칸 끝의 지우기 ✕는 쓰지 않습니다. 대상이 20px로 작고 키보드로는 따로 익혀야 하기 때문입니다.
- 필수 칸에는 '조건 없음' 항목을 두지 않습니다.
- 열린 목록의 폭은 칸 폭 이상, 내용에 맞춰 최대 360px(`--list-max-width`)입니다. 10개가 넘으면 목록 안에서 스크롤합니다. 아래에 자리가 없으면 칸 위로 열립니다.
- 열리고 닫힐 때 150ms 페이드입니다('모션').
- 키보드: ↓·Enter·Space로 열고, ↑↓로 이동, Home·End로 처음과 끝, Enter로 고르고, Esc로 닫습니다. 글자를 치면 그 글자로 시작하는 항목으로 갑니다. 검색 칸이 있으면 열 때 검색 칸에 포커스가 가고, 한글을 조합하는 중의 Enter로는 고르지 않습니다.
- 읽기 전용 선택 상자(맥락 칸)는 목록 없이 값만 가라앉은 칸에 보입니다. 포커스와 복사는 됩니다.

코드: `frontend/src/shared/ui/TextInput.tsx`, `Select.tsx`. 화면은 `<input>`, `<select>`를 직접 쓰지 않습니다. 동작(키보드, 스크린 리더, 목록 위치, 검색)은 React Aria Components가 맡고, 모양은 `field.module.css`와 `Select.module.css`가 토큰으로 그립니다(ADR-0007).

```tsx
<form onSubmit={search}>
  <Select
    label="공장"
    required
    items={plants}
    value={plant}
    onChange={setPlant}
    error={plantError}
  />
  <Select
    label="Shop"
    emptyLabel="전체"
    items={shops}
    value={shop}
    onChange={setShop}
    disabledReason={plant ? undefined : "공장을 먼저 선택"}
  />
  <TextInput label="LOT 번호" code value={lot} onChange={setLot} />
  <Button variant="primary" icon="search" type="submit">

  </Button>

```

- 항목은 `{ value, name, code?, meta? }`입니다. `code`가 있으면 `코드 · 이름`으로 보입니다. 고르지 않았거나 '전체'를 고르면 값은 `null`입니다.
- 비활성은 `disabledReason`으로만 만듭니다(버튼과 같음). 오류는 `error`, 필수는 `required`, 읽기 전용은 `readOnly`입니다.
- 코드 칸(LOT, P/N 입력)은 `TextInput`에 `code`를 줍니다.

### 버튼

| 종류   | 모양                        | 쓰는 곳                                                   |
| ------ | --------------------------- | --------------------------------------------------------- |
| 주요   | 본문색 면, 패널 색 글자     | 영역마다 하나: 조회, 저장, 다이얼로그 확인                |
| 보조   | 패널 면 + 강한 테두리       | 초기화, 취소, 복사, 이중 목록의 추가                      |
| 고스트 | 면과 테두리 없음, 보조 글자 | 그리드 툴바의 행 추가·행 삭제·엑셀, 토스트 동작, 에이전트 |

- 높이는 컨트롤, 안 좌우 12px, 모서리 4px, Medium입니다. 아이콘과 글자 사이는 4px입니다.
- 주요·보조 글자 버튼은 최소 폭이 `--button-min-width`(컨트롤 높이의 2배, 64px)입니다. 두 글자 버튼(취소, 저장, 삭제)의 폭이 같아져 확인 창과 폼 아래가 가지런합니다. 고스트와 아이콘만 있는 버튼에는 두지 않습니다.
- 아이콘은 화면에 늘 놓여 있어 눈으로 찾는 버튼에만 붙입니다: 조회 조건의 조회·초기화, 그리드 툴바의 도구(행 추가, 행 삭제, 엑셀), 이중 목록의 추가(뒤에 오른쪽 화살표). 저장, 확인, 취소, 삭제처럼 마무리하는 버튼은 확인 창과 폼 아래, 그리드 툴바 어디서든 글자만 씁니다. 무엇을 하는지는 확인 창의 질문과 버튼 글자가 이미 말하고, 휴지통 같은 아이콘은 겁을 주는 표시를 더하기 때문입니다.
- 대상 개수가 있으면 동사 뒤에 붙입니다: `저장 4건`, `추가 3`. 0이면 버튼을 비활성으로 둡니다.
- 삭제 버튼에도 빨강을 쓰지 않습니다. 빨강은 오류와 반려에만 씁니다. 삭제는 저장 전까지 행 편집 상태 `−`로 되돌릴 수 있게 합니다.
- 마우스 올림, 누름, 비활성, 처리 중은 '상호작용 상태'를, 작은 버튼은 '컨트롤 크기'를 따릅니다.

코드: `frontend/src/shared/ui/Button.tsx`. 화면은 `<button>`을 직접 쓰지 않습니다.

```tsx
<Button variant="primary" icon="search" onClick={search}>조회</Button>
<Button icon="reset" onClick={reset}>초기화</Button>                          // variant 기본값은 secondary
<Button variant="ghost" icon="add" onClick={addRows}>행 추가</Button>
<Button variant="ghost" icon="refresh" label="새로 고침" onClick={refresh} />  // 아이콘만: label이 이름과 툴팁
<Button
  variant="primary"
  count={changes}
  countUnit="건"
  busy={save.isPending}
  disabledReason={changes === 0 ? "저장할 변경이 없습니다" : undefined}
  onClick={submit}
>
  저장
</Button>
```

- 비활성은 `disabledReason`으로만 만듭니다. 이유가 툴팁과 보조 기술의 설명으로 함께 갑니다. `disabled` 속성은 받지 않습니다.
- 처리 중은 `busy`입니다. 누른 순간부터 `onClick`을 부르지 않고, 스피너는 0.3초 뒤에 아이콘 자리(아이콘이 없으면 글자 앞)에 돕니다.
- 이중 목록의 `추가 3 →`처럼 방향을 뜻하는 아이콘만 `iconPosition="end"`로 글자 뒤에 붙입니다.
- 개수는 `count`와 `countUnit`으로 넘깁니다. `formatNumber`로 표기되고, 0인데 비활성이 아니면 개발 중에 경고합니다.
- 기본 `type`은 `button`이라 폼을 실수로 보내지 않습니다. 폼을 보낼 버튼만 `type="submit"`을 줍니다.
- 모양을 바꾸는 `className`, `style`은 받지 않습니다. 자리는 감싸는 요소의 `display: flex`와 `gap: var(--gap-buttons)`로 잡습니다.

### Y/N 값

DB에 저장하는 Y/N 플래그(사용여부, 필수공정여부 등)는 세그먼트 `Y | N`으로 받습니다. MMD에는 이런 값이 많고 대부분 필수이며 중요합니다.

- 체크박스를 쓰지 않습니다. 체크박스에는 '아직 고르지 않음'이 없어 빈 상자가 곧 N이 됩니다. 새로 만들 때 빠뜨린 값이 그대로 N으로 저장되고, 고르지 않았는지 N을 골랐는지 구분할 수 없어 필수 검사를 할 수 없습니다. 빈 상자는 '비어 있음'으로 읽혀 N이 Y보다 가벼워 보이지만, 사용여부 N은 기준정보를 쓰지 않게 하는 중요한 값입니다.
- 글자는 `Y | N`입니다. 저장되는 값, 그리드에 보이는 글자, 레거시 화면, 사용자가 말하는 방식("Y로 바꿔")과 같습니다.
- 새로 만들 때: 명세에 기본값이 있으면 그 값을 골라 두고, 없으면 Y와 N 어느 쪽도 고르지 않은 채로 둡니다. 필수인데 비어 있으면 저장할 때 그 칸만 오류가 됩니다(`필수공정여부를 선택하세요.`).
- 읽기 전용은 가라앉은 칸에 `Y`, `N` 글자로 보입니다. 비었으면 `–`입니다.
- 그리드의 Y/N 열은 늘 `Y`, `N` 글자입니다(가운데, 열 폭 76px). 칸을 고르고 Y나 N 키를 누르면 바뀌고, 한글 입력 상태(ㅛ, ㅜ)에서도 됩니다(글쇠 자리 `KeyY`, `KeyN`으로 봅니다). Enter나 두 번 누르기로 Y, N 작은 목록을 열 수도 있습니다. 새 행은 기본값이 없으면 `–`이고, 저장할 때 빈 필수 칸은 '그리드 안 표시'의 검증 오류 셀이 되며 아래 상태줄에 `필수 칸 3개가 비어 있습니다.`를 보입니다. 실제 동작은 상용 그리드를 고른 뒤 그 그리드의 편집기로 맞춥니다.

코드: `frontend/src/shared/ui/YesNoField.tsx`

```tsx
<YesNoField label="사용여부" required value={useYn} onChange={setUseYn} />
<YesNoField
  label="필수공정여부"
  required
  value={requiredYn}                    // "Y" | "N" | null. 기본값이 없으면 null로 시작
  onChange={setRequiredYn}
  error={tried && requiredYn === null ? "필수공정여부를 선택하세요." : undefined}
/>
<YesNoField label="사용여부" readOnly value={route.useYn} onChange={() => {}} />
```

### 체크박스와 라디오

- 상자는 `--check-size`(16px, 크기 조정을 따름)입니다. 체크박스 모서리는 3px, 라디오는 원입니다.
- 테두리는 입력창 테두리이고, 마우스 올림 때 보조 글자색입니다(입력 칸과 같음).
- 체크하면 주요 버튼 면으로 채우고 패널 색으로 체크(2px 선)나 점을 그립니다. 세그먼트의 '채운 면 = 고른 것'과 같은 문법입니다. 일부만 체크한 머리글 상자는 가로줄입니다.
- 비활성은 면 없음 + 강한 테두리, 비활성 체크는 비활성 면 + 비활성 글자색 표시입니다. 비활성 이유는 마우스를 올리면 툴팁으로 보입니다.
- 포커스는 바깥 2px 링입니다. 누를 수 있는 영역은 라벨까지, 그리드에서는 칸 전체라 24px을 넘깁니다. 높이는 컨트롤이라 입력 칸과 같은 줄에 맞고, 그리드와 목록 안에서는 행 높이(`size="sm"`)입니다.
- 체크박스는 저장하지 않는 옵션(내려받기 옵션, 화면 설정, 다시 묻지 않기)과 여러 개 고르기(그리드 맨 앞의 행 고르기 열, 이중 목록의 원본 목록)에만 씁니다. 저장하는 Y/N 값은 위의 'Y/N 값'을 따릅니다. 스위치는 쓰지 않습니다.
- 라디오는 선택지마다 설명이 필요할 때만 씁니다(주로 확인 창과 설정 화면). 세로로 쌓고, 설명은 선택지 아래 text-xs 보조 글자입니다. 짧은 선택지 2~4개는 세그먼트, 5개 이상은 선택 상자를 씁니다. 조회 조건과 그리드에는 라디오를 쓰지 않습니다.

코드: `frontend/src/shared/ui/Checkbox.tsx`, `RadioGroup.tsx`

```tsx
<Checkbox checked={includeHidden} onChange={setIncludeHidden}>숨긴 열도 내려받기</Checkbox>
<Checkbox size="sm" label="1010 고르기" checked={picked} onChange={setPicked} />   // 글자 없이 상자만
<RadioGroup label="내려받을 열" value={columns} onChange={setColumns} options={[
  { value: "visible", label: "보이는 열", description: "화면에서 숨긴 열은 빼고, 지금 순서대로 내려받습니다." },
  { value: "all", label: "모든 열", description: "숨긴 열과 코드 열까지 모두 내려받습니다." },
]} />
```

### 세그먼트 버튼

- 고른 쪽은 주요 버튼 면, 나머지는 보조 글자입니다. 바깥은 강한 테두리, 모서리 4px입니다. 고르지 않은 칸의 마우스 올림과 누름은 '상호작용 상태'의 면을 얹습니다.
- 높이는 컨트롤입니다. 사이드 메뉴의 화면 설정처럼 좁은 곳은 행 높이를 씁니다.
- 모든 칸은 가장 긴 글자의 폭을 따르고(같은 폭), 한 칸은 적어도 정사각형입니다. 고른 면이 옮겨 다녀도 크기가 같고, '위'처럼 짧은 선택지도 누르기 쉽습니다.
- 라벨은 다른 칸처럼 위에 둡니다. 툴바처럼 라벨 자리가 없는 곳은 라벨을 화면에서 숨기고(`hideLabel`) 보조 기술에만 알립니다.
- 키보드 포커스는 묶음 테두리에 잘리지 않게 칸 안쪽에 그립니다. ←→로 옮겨 고릅니다. 오류는 묶음 테두리가 negative이고 아래에 문구를 둡니다.

코드: `frontend/src/shared/ui/SegmentedControl.tsx`

```tsx
<SegmentedControl
  label="기준 행"
  hideLabel
  value={anchor}
  onChange={setAnchor}
  options={[
    { value: "below", label: "아래" },
    { value: "above", label: "위" },
  ]}
/>
```

### 그리드

상용 그리드의 테마 변수에 아래 값을 연결합니다. 제품별 세부는 그리드를 고른 뒤 정합니다.

| 요소         | 규칙                                                                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 상자         | 패널 면, 구분선, 모서리 6px                                                                                                                                     |
| 툴바         | 왼쪽: 제목 text-md SemiBold + `총 8건` 보조 글자. 오른쪽: 편집 도구 → 기타(엑셀) → 구분선 → 주의 메시지 → 저장                                                  |
| 머리글       | bg-sunken, text-xs SemiBold 보조 글자, 아래 강한 테두리                                                                                                         |
| 셀           | 행 높이, 좌우 8px, 구분선. 수량·값은 오른쪽 정렬, 코드는 숫자로만 되어 있어도 식별자라 왼쪽 정렬. 모든 셀에 `tabular-nums`, 영문·숫자가 섞인 코드 열에만 `zero` |
| 열 순서      | 체크박스(여러 행 고르기) → 편집 상태 → No → 핵심 열(코드) → 나머지                                                                                              |
| 현재 행      | 선택 면 + 첫 칸에 본문색 2px 막대. '선택됨' 같은 글자 열을 두지 않습니다                                                                                        |
| 셀 포커스    | 안쪽 2px 본문색                                                                                                                                                 |
| 편집 중인 셀 | 안쪽 2px 본문색 + 편집기. 선택 상자 편집기는 오른쪽에 화살표                                                                                                    |
| 아래 상태줄  | text-xs. 왼쪽에 오류 요약(negative), 오른쪽에 `선택 1`과 쪽 정보                                                                                                |

행 편집 상태 (저장 전)

| 표시 | 뜻   | 행 모양                                           |
| ---- | ---- | ------------------------------------------------- |
| `+`  | 신규 | 그대로                                            |
| `•`  | 수정 | 그대로                                            |
| `−`  | 삭제 | 모든 칸 안내 글자, 핵심 칸(공정, 코드)에만 취소선 |

- 편집 상태 열은 폭 28px, 머리글은 비우고, 표시는 본문색 Bold입니다. 툴팁과 `aria-label`로 '신규', '수정', '삭제'를 알립니다.
- 무채색으로 둡니다. 에이전트 바이올렛, 정보용 파랑과 겹치지 않게 하기 위해서입니다. 서버 목업의 '신규 (저장 대상)' 배지와 행 전체 파란 강조를 이것으로 바꿉니다.
- 아래 상태줄에 `+ 신규 2 · • 수정 1 · − 삭제 1`을 보여 줍니다.
- 취소선은 Y/N 같은 짧은 글자에 긋지 않습니다. 취소선을 그은 Y, N은 ¥, ₦처럼 보입니다.

편집 그리드의 칸

- Y/N 열: 편집할 수 있든 없든 `Y`, `N` 글자입니다. 열 폭은 76px입니다. 편집은 Y·N 키와 작은 목록으로 합니다('Y/N 값').
- 편집할 수 없는 칸(해당 없음, 자동으로 채워진 값): bg-sunken + 안내 글자입니다. 값이 없으면 `–`를 씁니다. 조회 전용 그리드에는 이 면을 쓰지 않습니다.
- 상태 열은 '기준정보 상태' 배지를, 오류 셀과 에이전트가 바꾼 셀은 '그리드 안 표시'를 따릅니다.

### 행 추가 도구

- 따로 패널을 두지 않고 그리드 툴바의 편집 도구 자리에 둡니다: 행 수 입력(폭 56px), 기준 행 세그먼트(아래 / 위), 행 추가(고스트, 앞에 + 아이콘), 행 삭제(고스트).
- 새 행은 현재 행의 아래나 위에 `+` 상태로 들어가고, 첫 편집 칸에 포커스가 갑니다.

### 이중 목록

- 왼쪽 원본 목록, 가운데 버튼 열, 오른쪽 대상 그리드를 2 : 버튼 : 5 비율로 둡니다. 본문 폭이 900px 미만이면 위아래로 쌓습니다.
- 원본 목록은 체크박스로 여러 개를 고르고, 툴바에 `9건 · 3건 고름`을 보여 줍니다.
- 가운데 버튼 열에는 추가 옵션(예: '추가할 때 필수공정' 세그먼트)과 보조 버튼 `추가 3`(뒤에 오른쪽 화살표)을 둡니다.
- 추가된 행은 대상 그리드에 `+` 상태로 들어갑니다.

### 상세 폼

- 패널 면, 구분선, 모서리 6px, 안 여백 12px입니다. 머리에는 제목 text-md SemiBold와 대상 ID(`Route 상세 · RT-0102`)를 둡니다.
- 칸은 180px(`--form-column-min-width`) 이상의 열로 채우고, 긴 칸(설명)은 두 열을 차지합니다. 라벨은 칸 위입니다. 편집 칸과 읽기 전용 칸은 '입력 칸 상태'로 구분합니다.
- 비워도 되는 선택 상자는 목록 맨 위의 '없음'으로 비웁니다.
- 버튼은 폼 아래 오른쪽에 취소(보조), 저장(주요) 순서로 둡니다.
- 상세 폼만 있는 화면은 폼 폭을 `--form-max-width`(960px)까지로 둡니다.
- 코드: `<DetailForm title="Route 상세" targetId="RT-0102" onSubmit={save} actions={...}>{칸}</DetailForm>`, 두 열 칸은 `<FormWide>`로 감쌉니다 (`shared/ui/DetailForm.tsx`). 상세 폼만 있는 화면은 `standalone`을 줍니다.

### 빈 상태

- 패널 면, 구분선, 모서리 6px, 안 여백 32px, 가운데 정렬입니다. 점선 상자를 쓰지 않습니다. 그리드 상자 안에 둘 때는 상자 테두리를 겹치지 않게 면과 테두리를 뺍니다(`bare`).
- 안내 글자색 아이콘 24px, 제목 text-md SemiBold, 설명 text-sm 보조 글자 순서입니다.
- 제목은 다음에 할 일을 말합니다: "공장과 Shop을 선택하고 조회해 주세요."

### 오류를 보이는 자리 (결정)

오류는 일이 일어난 자리에 보입니다. 사용자가 무엇이 안 됐는지, 어디를 고쳐야 하는지 그 자리에서 알 수 있게 하기 위해서입니다.

| 상황                                                 | 보이는 자리                                                                                                                                               |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 입력 칸의 값이 틀림(저장 전 검사)                    | 칸 아래 문구('입력 칸 상태')                                                                                                                              |
| 조회 실패                                            | 그리드(목록) 자리에 오류 상태: 오류 아이콘, `조회하지 못했습니다.`, 서버가 준 사용자 메시지, 추적 ID, `다시 조회`                                         |
| 저장 실패: 행의 값이 서버 검사에 걸림                | 걸린 칸이 검증 오류 셀('그리드 안 표시'), 아래 상태줄에 `저장하지 못했습니다. 오류 1건`, 이유는 오류 토스트. 고친 값은 그대로 남아 고쳐서 다시 저장합니다 |
| 저장 실패: 행과 상관없음(서버 연결, 권한, 시간 초과) | 오류 토스트(이유, 추적 ID, `추적 ID 복사`)                                                                                                                |
| 화면 자체를 그리지 못함                              | 화면 본문 자리에 `화면을 표시하지 못했습니다.`                                                                                                            |

- 조회 실패를 토스트로만 알리지 않습니다. 그리드가 비어 '결과 없음'처럼 보여, 토스트를 놓치면 실패를 결과 없음으로 읽습니다.
- 오류를 확인 창(메시지 상자)으로 보이지 않습니다. 확인을 누르면 내용이 사라져 어느 행을 고쳐야 하는지 기억해야 하고, 추적 ID를 옮겨 적기 어렵고, 오류마다 화면이 막힙니다.
- 오류 토스트는 사용자가 닫을 때까지 남습니다.
- 오류 문구는 '표기와 문구'의 오류 규칙을 따릅니다. 서버의 기술 메시지(SQL, 예외 이름)는 보이지 않고 추적 ID로만 찾습니다.

### 확인 창을 띄우는 때 (결정)

되돌릴 수 없는 일을 하기 전에만 띄웁니다. 확인 창이 잦으면 읽지 않고 누르는 습관이 들어, 정말 위험할 때도 그냥 넘어가기 때문입니다.

| 상황                                                      | 확인 창                                        | 문구                                                                                                  |
| --------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 고친 행만 있는 저장                                       | 띄우지 않음. 바로 저장하고 성공 토스트         |                                                                                                       |
| 삭제(−)가 든 저장                                         | 띄움                                           | `삭제 2건을 포함해 6건을 저장할까요?` / `삭제한 공정 정책은 되돌릴 수 없습니다.` / `취소`·`저장`      |
| 저장하지 않은 변경이 있는데 다시 조회, 탭 바꿈, 화면 닫기 | 띄움                                           | `저장하지 않은 변경 4건을 버릴까요?` / `다시 조회하면 고친 내용이 사라집니다.` / `취소`·`버리고 조회` |
| 행 삭제 버튼                                              | 띄우지 않음. 바로 `−` 표시(저장 전까지 되돌림) |                                                                                                       |
| 조회, 초기화, 엑셀 내려받기                               | 띄우지 않음                                    |                                                                                                       |

- 처음 포커스는 `취소`에 둡니다. Enter를 무심코 눌러도 진행되지 않습니다. Esc는 취소이고, 막을 눌러도 닫히지 않습니다(둘 중 하나를 고르게 합니다).
- 하는 일 버튼은 '확인', '예' 대신 동사로 씁니다. 빨강을 쓰지 않습니다.

코드: `shared/ui/ConfirmDialog.tsx`

    !(await confirm({

### 토스트

- 화면 오른쪽 아래(가장자리 16px), 폭 360px(`--toast-width`), 떠 있음 1단계, 안 여백 12px·16px, 모서리 6px입니다.
- 앞 아이콘, 제목 SemiBold, 설명 text-xs 보조 글자, 오른쪽에 고스트 동작 버튼(높이는 행 높이)을 둡니다.
- 면은 늘 떠 있는 면이고, 아이콘 색만 의미색을 씁니다. 결과 안내는 안내 글자색 아이콘, 성공은 positive, 오류는 negative입니다.
- 결과 안내와 성공은 5초 뒤 사라집니다. 마우스를 올리거나 포커스가 있는 동안에는 멈춥니다. 오류는 사용자가 닫을 때까지 남습니다.
- 여러 개면 새 것이 아래(모서리 쪽)에 붙고 앞의 것이 위로 밀립니다. 한 번에 3개까지 보이고, 넘으면 오래된 것부터 뺍니다.
- 오류의 추적 ID는 줄여 보이고(`0f3a9c2e…7b41`), `추적 ID 복사`가 전체를 복사합니다.
- 스크린 리더에는 오류를 바로(assertive), 나머지는 차례로(polite) 알립니다.
- 제목은 끝난 일을 마침표 없이 씁니다(`저장했습니다`, `저장하지 못했습니다`). 설명에는 대상과 개수를 씁니다(`공정 정책 6건 (신규 2, 수정 3, 삭제 1)`).

- 떠 있음 2단계이고, 막이 앱 전체를 덮습니다. 폭은 최대 560px(`--dialog-max-width`), 안 여백 16px, 모서리 6px입니다.
- 제목 text-lg SemiBold, 설명은 보조 글자입니다. 버튼은 아래 오른쪽에 보조, 주요 순서로 두어 주요 버튼이 오른쪽 끝에 오게 합니다.
- Esc로 닫히고, 열려 있는 동안 포커스는 다이얼로그 안에서만 움직입니다. 닫으면 연 버튼으로 포커스를 돌려줍니다. React Aria의 Modal이 맡습니다.
- 메시지 미리 보기는 bg-sunken, 구분선, 모서리 4px 상자에 D2Coding text-sm으로 보여 줍니다.

## 화면 골격과 반응형

### 그리드 (원칙, 상용 그리드를 고른 뒤 구체화)

그리드의 반응형은 글자 크기가 아니라 열 배치로 합니다. 글자 크기는 위의 단계를 따릅니다.

- 코드, 숫자, 날짜 열은 내용에 맞춘 고정 폭입니다. 공정명, 비고처럼 긴 글 열이 남는 폭을 차지합니다.
- 체크박스, No, 코드 같은 핵심 열은 왼쪽에 고정하고, 폭이 모자라면 나머지 열을 가로 스크롤합니다.
- 폭이 좁을 때(노트북에서 에이전트 패널을 연 경우 등) 수정자, 수정일시처럼 덜 중요한 열을 숨기거나 상세 패널로 옮깁니다. 열마다 우선순위를 둡니다.
- 열 순서, 너비, 숨김은 사용자별로 저장합니다.
- 행 높이는 고정 숫자로 그리드에 넘깁니다. 위의 표에서 현재 조합에 맞는 값을 씁니다.

### 화면 골격 (결정)

| 영역          | 규칙                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 앱 위쪽 막대  | 두지 않습니다. 로고, 메뉴, 화면 설정, 사용자는 사이드 메뉴에 있고, 그만큼 그리드에 높이를 줍니다                                |
| 사이드 메뉴   | 왼쪽, 폭 `--nav-width`(232px). 로고 줄 오른쪽의 접기 버튼으로 접고, 사용자가 접은 상태는 창 폭과 상관없이 사용자별로 기억합니다 |
| 화면 머리     | 제목과 ID 줄, 오른쪽에 에이전트 버튼. 메뉴가 접혀 있으면 제목 왼쪽에 메뉴 버튼(아이콘만, `menu`). 스크롤하지 않습니다           |
| 탭            | 탭이 있는 화면은 화면 머리 바로 아래                                                                                            |
| 조회 조건     | 화면 머리 아래. 스크롤하지 않습니다                                                                                             |
| 작업 영역     | 남은 높이를 채웁니다. 그리드 안만 스크롤하고, 그리드 툴바와 머리글은 그대로 있습니다                                            |
| 에이전트 패널 | 오른쪽에 붙습니다. 폭 `--dock-width`(360px). 그리드를 덮지 않습니다                                                             |
| 본문 폭       | 창 폭을 채웁니다. 그리드 화면에는 최대 폭을 두지 않고, 상세 폼만 있는 화면은 폼을 `--form-max-width`(960px)까지로 둡니다        |

스크롤

- 화면 머리, 탭, 조회 조건, 그리드 툴바와 머리글은 그대로 두고 그리드 안만 스크롤합니다. 조회 조건을 바꾸거나 저장하려고 위로 올라갈 일이 없고, 데스크톱 레거시 화면과 같습니다.
- 창 높이가 560px 미만이면(브라우저 200% 확대, 낮은 창) 화면 전체를 스크롤합니다. 그리드가 몇 줄로 납작해지지 않게 하기 위해서입니다. 이때도 그리드 머리글은 위에 붙어 있습니다.
- 화면 전체 스크롤을 기본으로 하지 않은 이유: 행을 내리면 조회 조건과 저장 버튼이 화면 밖으로 사라집니다.

접힌 메뉴

- 메뉴가 접히면 화면 제목 왼쪽의 메뉴 버튼을 누를 때 메뉴가 서랍처럼 왼쪽에서 덮어 열립니다. 막(2단계)이 깔리고, 항목을 고르거나 바깥을 누르거나 Esc를 누르면 닫힙니다.
- 아이콘 막대로 접지 않습니다. 메뉴 묶음마다 아이콘이 있어야 하는데, 기준정보 화면은 아이콘으로 구분하기 어렵고 아이콘만으로는 화면을 찾기 어렵습니다.

목록과 상세

- 목록 그리드와 상세(하위 그리드나 상세 폼)가 함께 있는 화면은 상세를 목록 아래에 둡니다. 사이의 손잡이로 높이를 나누고, 처음에는 반반입니다. 나눈 비율은 화면별로 기억합니다.
- 오른쪽에 두지 않는 이유: 그리드는 높이보다 폭이 모자랍니다. 1280px 창(gram 150%)에서 상세를 오른쪽에 두면 목록이 500px대로 좁아집니다.

### 화면 배치 구간 (결정)

창 폭(CSS px)으로 나눕니다. 위의 모니터 보정(모니터 폭 기준)과는 따로입니다. 구간 값은 컨테이너 쿼리에 숫자로 씁니다(CSS 변수를 쓸 수 없습니다).

본문(작업 영역) 폭에 따라

- 900 미만: 이중 목록을 위아래로 쌓습니다(원본 목록, 버튼 줄, 대상 그리드).
- 640 미만: 조회 조건 칸이 한 줄에 하나씩 놓입니다.
- 그리드는 열 배치로 맞춥니다(위 '그리드' 원칙).

코드: 앱 틀은 `shared/ui/AppShell.tsx`, 화면 안 배치는 `shared/ui/Screen.tsx`입니다. 메뉴는 `src/app/menu.ts`에 둡니다.

```tsx
// src/app/App.tsx
<AppShell menu={menu} current={screenId} onNavigate={setScreenId} menuSearch={MENU_SEARCH}>
  <ScreenHost screenId={screenId} />
</AppShell>

// 화면 View

  <ScreenHeader title="공정 정책 관리" ids={["PANEL_TPFOPOLICY", "레거시 SIC01061"]} />
  <QueryBar onSearch={search} onReset={reset}>...</QueryBar>
  <WorkArea>{그리드}</WorkArea>

```

- 구간 값(1440, 1024)은 `AppShell.tsx`의 상수, 본문 폭 구간(900, 640)은 컨테이너 쿼리(`@container main`)에 씁니다.
- 고칠 수 있는 화면은 `useLeaveGuard(저장하지 않은 변경 수)`를 부릅니다. 0보다 크면 다른 화면으로 옮길 때 확인 창을, 창을 닫을 때 브라우저 확인을 띄웁니다.
- 메뉴를 접은 상태, 펼친 묶음, 화면 설정은 브라우저에 기억합니다. 로그인이 생기면 사용자 설정(BE)으로 옮깁니다.
